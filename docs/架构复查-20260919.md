## A. 先修这些 —— 是真 bug，不是结构偏好

### A1. 自动保存对参数类编辑完全不起作用

**位置** `src/lib/autosave.ts:27-53`（`signature` / `shouldWrite`）、`channels/Channels.svelte:515-527`（`maybeAutosave`）、`530-536`（`checkRecoverable`）

`signature()` 只统计**图层数、操作数、混合层数、槽位路径**。于是：

- 拖动图层不透明度 → 计数不变 → 签名相同 → `shouldWrite` 返回 false → **不保存**
- 换混合模式、改蒙版、改曲线 → 同上

也就是说，自动保存**恰好对它存在的意义——那些编辑——不生效**。同一个浅比较还驱动了 `checkRecoverable` 的"跟当前状态一样的就不用提示了"，把真正的恢复提示也压掉了。

**改法**：用一个诚实的相等判断，或者在 `commit`（`503`，唯一的编辑入口）里递增一个 revision。
**注意**：`tmp/autosave.test.mjs:103-123` 现在把"只对计数/路径敏感"这件事**固化成了断言**，改的时候要一起改。
**补一条测试**：在已有的接缝上加一行——「计数相同、参数不同 ⇒ 必须写」。

### A2. 图层缓存对超过 320px 的图永远命中不了

**位置** `channels/ops.ts:82-92`（`objId`/`idSeq`）、`100-136`、`841-849`；调用方 `Channels.svelte:364-371`、`425-432`、`263-275`；`img.ts:263-268 previewOf`

`LayerCache` 的键是**对象身份**。而 `previewOf` 在源图超过 `PREVIEW = 320`（`Channels.svelte:104`）时**返回一个新的 `ImageData`**；三个调用方又各自在 `raf.schedule` 回调里新建 `Map`。

结果：只要贴图大于预览边长，每次重算都铸出新身份，`layerKey` 全变，**缓存一次都不可能命中**。面板上还显示着那个计数器（`lyStats` `420` → 渲染在 `1648`）。

`ops.ts:10-14` 写的那个承诺只在"图本来就小于预览边长"时成立，而"每次传同一批 `ImageData` 对象"这个不变量**没有任何地方强制**。

**改法**：给 `previewOf(src, side)` 加按"源身份 + 边长"的记忆化，把不变量放到建键的地方。
**补一条测试**：`tmp/channels-ops.test.mjs:371-397` 现在用的是一个**复用的 `Map`**，比真实用法窄——要补调用方那一段。

```js
const next = ids.includes(want) ? want : (cur && ids.includes(cur) ? cur : (mod.panel ?? ids[0]));
```

**改法**：`cur` 改成从 `page.url` 派生的只读值，只留一处规范化写入。7 行协调器、三个边界情况、以及"地址栏和屏幕不一致"这一整类问题一起消失。

### B3. 注册表里那份 eager import 是一个根因、三个症状

**位置** `registry.ts:14-26`（13 个静态组件 import）、`quick.svelte.ts:43-69,120-132,192-200`、`Quick.svelte:26`、`tmp/alias-loader.mjs:6-11,20-23,40-45`、`tmp/work-pages.test.mjs:8-16`

### B8. 槽位 id 是字符串字面量，每个面板重复 4-6 次

**位置** `wb.svelte.ts` `get()` `51-53` 返回 `this.map[id]`，而所有修改器都写 `if (!s) return`（`57,69,96,124,146`）；`Channels.svelte` 在 `Slots` 定义（`338-343`、`410-415`）、标记里的 `{#each ['base','top','top2','top3']}`（`1558`）和 `{#each ['diffuse','lightmap','s3','s4']}`（`1629`）、`LayerStack` 的 `slots=` 属性（`1590-1595`、`1724-1729`）与 `reserved`（`1596`）、`LY_SLOT_IDS`（`611`）、`BATCH_SLOT_IDS`（`774`）、`project.ts` 的槽位重建（`620`）、`LayerStack.svelte:83-89,104-106,128-133` 里各写一遍。

### G1. 又是两条 rune 缓存 bug —— 一张死卡片，一个冻住的时间戳

**（a）`Ilm.svelte:147` 漏了 `$state`**

```js
let packed: ImageData | null = null;      // ← 普通 let，不是 $state
```

它只在打包 effect（`168`）里被赋值，只被 `const stats = $derived.by(...)`（`205-213`）读，渲染进「各通道分布」那张卡（`536-554`）。
