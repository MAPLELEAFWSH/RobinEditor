## 1. 四条路（术语以用户原话为准，别自己换词）

**自包含目录** = "**打包工程所有需要的文件到指定位置，并可以正常打开使用**"。

### A. 原地修复（默认）

文件都在盘上、只是工程里的路径死了。工具按"新根 + 原相对尾部"把路径改回去，
**默认原地改、留 `.bak`**（用户口径：文件都在的话，只需要修复工程文件）。

1. **拖入一个 `.pmm` 就够了**：同名的 `.emm` 自动接上，并**立刻扫一遍出表**（不用再选第二遍）；
2. **自动识别工程内容文件现在存在哪儿** —— 把工程里引用的**模型**与**附件**各自所在的目录归出来
   （常见的是一堆模型散在两三个目录里），**不是让用户一个个填**；
3. **让操作者指定新位置，分两部分：模型 / 附件**（各自的目录），**可多组**；
4. **保存**：把工程里的路径改到新位置；写盘后**回读核对**（新路径没落进文件、或旧路径还留着就报错）；
5. **模型「名称」**（对齐参考工具那页）：**能看**（表里一列 + 名称板块）；
   **能改，但只放行"等长"改名**（改长度会让本工具的结构自检失效，实测 8/8，见格式规格 §41）。
   改长度**不做**，不是没做，是"量不清就不做"。

### B. 检索（文件被挪走、不知道在哪儿）

给若干搜索起点，工具**按文件名**找，用"尾部还能对上几段"判断是哪一份；
**唯一命中才自动填，并列就列候选交人挑** —— 不许自己猜。
在测试/临时目录里找到的候选降级成"待确认"，不给自动建议。

### C. 搬运（把文件真的搬/拷过去）

用户 2026-09-22 原话：「看一眼要动哪些文件后，对文件都在的情况可以选择将文件迁移到指定位置
（单选或多选都可以）然后保存，工程文件迁移也可以做到修复」。

- 每一组算出来的根挑**一个目标位置**，**可以多组**（模型放 A、特效放 B）；
- **默认「拷贝」**（原件留着）；选「移动」只在**逐个字节核对相同**之后才删原件；
- 连根旁边的贴图一起搬；**目标落在源里面直接拒绝**（否则会自己拷自己）；
- 搬完**再把工程里的路径改到新位置并保存** —— 所以它同时就完成了 A（修复）。

### D. 自包含目录

把工程用到的所有文件连同 `.pmm`/`.emm` 拷到一个目录，**两份工程文件里的路径改指包内**，
**打包工程所有需要的文件到指定位置，并可以正常打开使用**。
只丢出 `.pmm`/`.emm` 两个文件是**错的**（用户报过"只丢出一个 1 文件"）：
模型/贴图/特效/附件必须一并拷进去，并报出**拷了几个文件、多少 MB**。
**实测**（撤销量具 ④ 里钉住的）：包里那两份工程文件写的是**包内的完整路径**（`…\包\模型\x.pmx`，GBK），
不是相对路径 —— 接收方按自己放的位置再改一次就行（那就是 A 那条腿）。

> **这条腿原来有个缺口，2026-09-23 按用户拍板的「改法 1：不漏」修掉了**：自带原来只处理**被规则命中**的路径，
> 工程里本来就指对（盘上有）的那些根不在「要改的根」里、也不在逐条表里 → 文件不进包、路径也不改，
> 包里那份仍指着包外，整包搬走会缺模型（量具原来叫 `打包_没被规则覆盖的健康路径会漏在包外_现状`）。
> **现在**：
>
> - 没被规则覆盖、但盘上确实有的路径**也进拷贝清单**，尾部取「源目录名\文件名」（连它的邻居一起拷），
>   并进写表改指包内；
> - **一条映射都不给也能打包**（工程本来就健康 → "只想打个包"**有入口**，界面与后端都放行）；
> - **同名不同内容**仍按原来那道闸整体拒绝（换个空目录，或先把同名的那几个改名）；
> - 输出目录落在源目录**里面**时拒绝（会自己拷自己、越拷越深）；
> - 量具：`打包_没被规则覆盖的健康路径也进包_连邻居一起`、`打包_工程本来就健康时没有映射也有入口`、
>   `打包_同名不同内容时按原来的闸拒绝并说清楚`。

### 不做的事（用户明确）

- **"文件丢失就摘条目"整条不做** —— 用户 2026-09-22："不要做文件丢失的情况了"。
  缺文件**只报告**，界面上一处都不留。
- **VMD 不用管**：实测 363 个 `.pmm`/`.emm` 里**一处 `.vmd` 引用都没有**，动作数据嵌在
  `.pmm` 的模型帧区里。所以"工程内的 vmd 一起成功载入" = **不许碰帧区**，
  靠"所有差异字节必须落在被改写的 256 字节字段内"这条硬检查保证。
- 动作用户自己上，工具只负责"工程能打开、路径对"。

## 2. 与已实测格式的对应关系（别自己另发明）

- `.pmm` 对象路径 = **定长 256 字节、GBK**，靠 `.emm` 锚定位，覆写**不改文件长度**（实测）。
- `.emm` = 纯文本 INI（CRLF/GBK），`[Object]` 是 `Acs<N>/Pmd<N> = 路径`；模型与附件**共用槽位号**。
- 删条目后 `.emm` 的编号前移规则**已在真文件副本上验证**（删 33 键、前移 56 键、编号 1..49 不重不漏、
  `[m]` 材质序号不变、`[Effect]` 里的 `Pmd<N>`/`Acs<N>` 跟着改）。
- 计数：**`0x36..0x37` 是 uint16 = 模型数**（删模型按 16 位写回，只动一个字节在 >255 时会错）；
  **`0x35` 含义未知、不许动**。
- **模型帧区里没有"第几个模型"的槽位号**（479 个帧区实测，无恒定常数）→ 删模型**不必改**其余帧区。
- 附件块首 u32 = 0 起序号（量实）；**附件数找不到** → 删附件做不了（这条已经整条不用了）。
- `.pmx` 贴图路径 = 长度前缀字符串、材质按**索引**引用 → 改长度安全、**删表项不安全**。

## 3. 验收

1. A 原地修复：拿**真的坏工程**跑一遍，**只有路径字段变化、文件长度不变、其余逐字节相同**。
   实测（日间那套，84 条指 `D:\MMD一键渲染工程项目` + 1 条指 `H:\UserFile`）：
   `.pmm` 13231 → 13231 字节、改字段 15 处、`.emm` 改行 85 行、旧根归零、85/85 落在盘上、帧区原样。
   保存后的工程能被 MMD 打开（打开这件事由用户验，工具这边先保证"与原件只差路径字段"）。
   **反面**：工程本来就在原位（`找死根` 的建议就是它自己）时，**必须说清"没有需要改的地方"并拒绝写盘**，
   一个字节都不动 —— 不许报"旧根还剩 N 次"这种看不懂的错（实测夜间那套就是这个状态）。
2. C 搬运：多组目标 + 拷模式 —— 文件到位、工程路径指到新位置、**原件仍在**
   （实测 拷 1160 个 / 197.0 MB、源目录 1221 → 1221 不变）；移动模式只在逐字节相同后才删；
   目标落在源里必须拒绝；干跑不许碰盘（实测干跑不生成任何产物目录）。
3. D 自包含：报出**拷了几个文件 / 多少 MB**，且每条路径都指向包内（实测 1160 个 / 197.0 MB、172/172 命中）。
4. 撤销：**写盘前先落记录**，撤销照记录反着做；预检有一条不过就整体拒绝；撤销完回读核对。
   四条腿都量过（`cargo test --lib 撤销`，量具 `撤销_原地修复写回改前那份_搬模式把原件搬回原位`）：
   ① 原地修复撤销后 `.pmm`/`.emm` **逐字节回到改前**、干跑一个字节不动；
   ② 搬模式撤销后**原件回到原位且内容一致**、新位置那份撤掉、副本目录删掉、工程文件回到搬之前；
   ③ 没有记录时只说"没有可撤销的记录"，不动盘；
   ④ **打包迁移撤销后包里的 `工程.pmm`/`工程.emm` 被删、`包\模型\` 整棵删掉、源工程逐字节没被动过、素材一个不少**。
   > ④ 的 `回读` 天然是空的：自带模式**从没改过原处的任何文件**（只往包里写），记录里 `改前`/`原件` 两张表本来就没东西。
   > 源工程"没被动过"由量具里的逐字节断言兜。
5. 全程**先出表给用户看、确认后才写盘**；写盘留 `.bak`、不覆盖已有文件。
6. 撤销在**真工程**上复跑：量具 `香港验收_撤销复跑_修复区与打包区`（`--ignored --nocapture`，
   夹具 = 真工程副本 1223 个文件，记录目录用 `ROBIN_撤销目录` 指到工作目录、**不碰用户真实记录**）——
   修复区 改字段 15 / 改行 85 → 撤销写回 2 个文件、回读 2 条全过、逐字节回到改前；
   打包区 拷 1160 个 / 197.0 MB → 撤销删掉包里 2 个工程文件 + 4 个副本目录、源工程逐字节没被动过。

## 4. 撤销 / 还原（用户 2026-09-22："指定路径错了可以还原"）

**记录什么**（`%APPDATA%\com.robineditor.app\undo\<时间>-<动作>\`，留最近 30 次）：
时间 / 动作 / 方式 / 工程文件路径 / **改前 `.pmm`+`.emm` 的整份副本（含字节数与校验）** /
这次新写出来的产物 / 拷出来的目录对（源 → 目标 + "目标本来就在吗"）/ 「搬」模式删掉的原件（原、新、字节、校验）/
`已撤销` 标记。

**为什么不用 `.bak` 当唯一还原源**：连做两次就把上一次的 `.bak` 盖掉（现场实测就是这样），
而且实测现场有一份 `.emm` 连 `.bak` 都没有。改前副本一次才约 47 KB，留 30 次毫无压力。

**反着做**（顺序固定，保证任何中间态都不会"工程指向不存在的文件"）：

| 动作 | 撤销 |
| --- | --- |
| 原地修复 / 逐条指定 | 用记录里的改前副本整份写回 |
| 搬运（拷） | 先写回工程文件 → 再删这次拷出来的副本目录 |
| 搬运（搬） | **先把原件从新位置搬回原位**（逐字节比过）→ 再写回工程文件 → 再删副本目录 |
| 自包含 / 另存 | 删掉记录里列出的产物（**不是 `rm -rf` 整个包目录**）→ 工程文件按记录处理 |

**删副本目录的判据**：只删记录里 `目标本来就在 == false`（这次才造出来的）那些，
并且**必须"目标里的东西全都能在源里逐字节对上"**（目标 ⊆ 源）——
用户往里放过东西就一个都不删，只报告。搬模式撤销后目标里只剩"邻居副本"，正好落进这条。

**拒绝与边界**：记录里任何路径命中 `测试效果`/`\temp\`/`\tmp\`/`%TEMP%`/`robin-⑥` → 整体拒绝；
改前副本不在或对不上 → 拒绝；要搬回的原件已被改过 → 拒绝；原位置已有同名不同内容 → 拒绝；
动到一半失败就**停下如实报告，不自动回滚**；撤销成功标 `已撤销`（**只做"上一次"**）。

**界面**：底栏一个「撤销上一次处理」（没有记录就禁用 + 一行"没有可撤销的记录"）→
点了**先出表**（会写回哪几个文件、从哪个副本、要删哪些副本目录、要搬回哪些原件、预检问题）→
表下面「确认撤销」才真做 → 做完再给一份回读核对。

## 5. 怎么用（两区各自的"点通清单 + 每步预期"）

**模块位置**：侧栏「**工程**」分组 →「**工程迁移**」。两个区由分区条决定，页里不再有"哪种情况"的开关：

- **修复工程**（`?panel=repair`，默认）：只改路径 —— 文件不动，含"文件被挪走了指回来"；
- **打包迁移**（`?panel=pack`）：把工程引用的文件**连同** `.pmm`/`.emm` 一起拷到指定位置，路径改成指向包内。

### 7.2 怎么做的（口径与踩过的坑）

- **记忆**：一个 localStorage 键 `robin.migrate.fold.v1`，形状 `{ "repair": { "逐条": false }, "pack": { … } }`。
  **按页 + 按区块**：换区不串（探针里 pack 区读到的还是自己的那份）。读出来的一律当不可信 ——
  不是对象、值不是布尔、JSON 截断了，都当"没记过"，回这一条自己的默认（探针里塞了坏 JSON 验过）。
- **开合只挂在各卡标题的点击上**（`<summary onclick>`），**不去听 `<details>` 的 `toggle`** ——
  体检脚本量"全展开"那一层是**直接把 `details.open` 打上去**的，听 toggle 就等于
  "量一遍顺手把这一页的记忆改成全开"，下一次进页面看到的就不是默认。
- **重置工程**顺带把这一页的折叠记忆清掉（同样只动 localStorage，不碰盘）。
- **动效**：`transform: translateY(-5px) → 0`，`var(--t-micro)`（200ms）+ `var(--ease-std)`，
  **位移一条、没有过冲曲线、没有缩放**；`data-motion='off'` 与 `prefers-reduced-motion` 下自动退化。
- **参数抽屉与折叠卡是两套**：抽屉里一个字节都没搬进折叠卡（打包区抽屉本来就是空的，修复区只有「原地修复」那个 checkbox）。
- 「每一处路径（逐条）」**改名「逐条指定」**（§十八 给的例子就是这个名字）；
  「更多工具」标题里**去掉了「找回挪走的文件」**（它提级成区块卡了）；
  底栏那句「先在 ③ 里选一个输出目录」改成「先在「自包含目录」那一行点「选目录」」（③ 现在没有编号标题了）。
