## 一、现场结论（**只读查的，一个字节都没动**）

查的范围：`E:\C test\达到\`、库里那份 `…\香港_by_胧月兔_…\UserFile\`。
量法：列目录 / 逐个文件 SHA256 / 按 GBK 解出 `.pmm`+`.emm` 里的路径并**逐条 Test-Path** /
拿"盛大的"三个字的 GBK 字节在工程文件里搜。

### 1. `盛大的\` 是**空目录**，什么都没进去

```
E:\C test\达到\盛大的\   →  0 个文件、0 个子目录（18:26:26 建的）
"盛大的" 这个串 在 5 份 .pmm/.emm（含 .bak）里出现次数 = 0 / 0 / 0 / 0 / 0
```

**结论**：那次"迁到盛大的"**没有产生任何结果** —— 目录被建出来了，但里面一条路径、一个文件都没有，
工程文件里也**没有任何一处指向它**。（用户看到的"空文件夹"就是这个。）

### 2. `达到\` 里现在**同时躺着三拨产物**，是不同尝试叠出来的

| 位置 | 规模 | 形状 | 这是哪条路留下的 |
| --- | --- | --- | --- |
| `达到\mmd集成工具\香港_by_胧月兔_…\UserFile\{ray-mmd-1.5.2, ikBokeh_v019, ikClut_Dec, 香港观瑭}` | **1160 个 / 197.0 MB**（18:23:50） | 把"旧根后面那一整段"原样带过来了 | **按根搬/打包**：目标当成了"新根"，于是多套了 `mmd集成工具\香港_by_胧月兔_…\UserFile` 这一长段 |
| `达到\模型\` + `达到\附件\` + `达到\特效\` | 126 + 3 + 29 个 / 67.5 MB（18:19 / 18:38） | **平铺**（`.pmx`、`.x`、`.fx` 各自堆在一个目录） | **按文件名指到一个目录**那条路（界面里 ③ 的"新模型目录/新附件目录"那一对） |

**7 份哈希两两不同**（没有两份是同一个内容）。要点：
- **库里的 `.pmm` 和 `.emm` 不是一个状态**：`.emm` 已指向 `达到\`，`.pmm` 还指向自己 → 这就是界面报
  「命中率 50% / 有 7 个对象的路径字段没定位到，写盘会改不全」的**真正原因**。
- **`达到\` 里的 `.emm` 没有 `.bak`**（那一层只有一个 `…夜间.pmm.bak`）→ 那份 `.emm` 一旦被改错，**同目录里没有原件可还原**。
- 库里那两份 `.bak` 还是 **2023-09-24 的真原件**（没被覆盖）。

### 4. 文件**没有丢**：我按每条路径逐条 `Test-Path`，全都存在

所以用户遇到的**不是"文件丢失"**（他早说了不做那种情况），而是：

> **目标位置指定得不对 → 工具照做了 → 工程文件里的路径被改成了不合预期的位置
> （多套一长段、或平铺到 `模型\`）；而且每改一次就覆盖上一次，`.bak` 只能回溯一步、
> 这次连 `.bak` 都缺一份 → 他现在没有任何办法回到改之前。**

### 5. 已经发生过的这一次，**回溯不了**

全盘翻过：`达到\` 底下**没有任何"操作记录"文件**（只有素材自带的那几个 `README.txt`/`LICENSE.txt`）。
工具现在**不写任何记录** —— 所以这次只能靠库里那两份 2023 年的 `.bak`（那是"修路径之前"的原件），
或者手工收拾。**这条必须在方案里说清楚：撤销能力从"以后每一次操作"开始有，救不了已经过去的这一次。**

## 二、方案样本（**不实现，先给用户看**）

### 0. 一句话

**每一次会写盘的操作都落一份"操作记录"（含改前的工程文件整份副本）；「撤销上一次处理」照这份记录反着做，
先用一张表告诉用户要动哪些文件、是删副本还是搬回原件，确认了才执行，执行完回读核对。**

### 1. 记录什么（`操作记录`）

一次按钮点击 = 一条记录。写盘前先落盘（**先记录、后动手**，这样中途崩了也知道做过什么）。

```jsonc
{
  "版本": 1,
  "时间": "2026-09-22T18:23:51+08:00",
  "动作": "原地修复",            // 原地修复 / 检索+修复 / 逐条指定 / 搬运 / 自包含打包 / 另存换根
  "方式": "",                   // 搬运才有："拷" / "搬"
  "工程": { "pmm": "E:\\…\\夜间 2.1.pmm", "emm": "E:\\…\\夜间 2.1.emm" },

  /* 改前的工程文件**整份存进记录目录**（`.pmm`+`.emm` 一共约 47 KB）。
     `.bak` 只当**交叉校验**：两边的哈希必须一致，不一致就拒绝撤销并说清。
     为什么不能只靠 `.bak`：连做两次就把上一次的 `.bak` 盖掉了（现场就是这样），
     而且 `达到\` 里的 `.emm` 连 `.bak` 都没有。 */
  "改前": [
    { "是": "pmm", "副本": "记录目录\\…\\改前\\夜间 2.1.pmm", "长度": 16840, "哈希": "6AA153BC…" },
    { "是": "emm", "副本": "记录目录\\…\\改前\\夜间 2.1.emm", "长度": 29200, "哈希": "AB95629A…" }
  ],

  /* 这次拷/搬出去的文件（撤销=删掉；搬模式撤销=搬回原位） */
  "产物": [
    { "新": "E:\\C test\\达到\\…\\ray.x", "字节": 448, "哈希": "…", "原件": "H:\\UserFile\\…\\ray.x", "删了原件": false }
  ],

  /* 这次改写过的路径（撤销=改回；同时是回读核对的清单） */
  "路径": [ { "段": "[Object]", "键": "Pmd2", "原": "H:\\UserFile\\…", "新": "E:\\…" } ],

  "摘要": { "拷贝文件": 1160, "拷贝字节": 206569472, "删除文件": 18, "改字段": 36, "改行": 172 },
  "已撤销": false
}
```

**放哪儿**（请用户拍）：① `AppData\com.robineditor.app\undo\` 一个操作一个文件（不碰工程目录）；
② 工程文件旁边放一个 `.robin-undo.json`（跟着工程走，但会在用户目录里留东西）；
③ 两边都写（AppData 当主，旁边只放一个指针）。**建议 ①**，保留最近 30 次。

### 2. 每种动作"反着做"是什么

| 动作 | 撤销 = |
| --- | --- |
| **原地修复 / 检索+修复 / 逐条指定** | 把记录里那份改前的 `.pmm`/`.emm` **整份写回**（`.bak` 哈希一致才写） |
| **搬运（拷模式）** | ① 先写回改前的工程文件（此时原件都还在，工程立刻回到"指原件"的状态）→ ② 再删这次拷出来的副本（**逐个按记录的哈希核对，不符就不删**）→ ③ 收掉空目录 |
| **搬运（搬模式）** | ① 先把**原件搬回原位**（新位置那份的字节要与记录一致；**原位置若已有同名不同内容的文件 → 拒绝**）→ ② 再写回改前的工程文件 → ③ 收掉空目录 |
| **自包含打包** | ① 删掉这次产出的**记录里列出的那些文件**（**不是 `rm -rf` 整个包目录**）→ ② 没删空的目录收掉 → ③ 若打包是原地改的，写回改前的工程文件 |
| **另存换根** | 删掉这次写到输出目录的那两个工程文件（**输出目录里记录之外的文件一个都不碰**） |

### 3. 执行规矩（照着本工程一贯的口径）

1. **先出表**：点「撤销上一次处理」先给一张表 ——
   · 要写回哪几个工程文件、从哪儿写回、`.bak` 哈希对不对得上；
   · 要删哪些副本（几个文件 / 多少 MB）**或**要搬回哪些原件（几个）；
   · 每条一行 ✓ / ✗ 和原因。
   **不列出这张表、不许执行。**
2. **预检全过才动手**：任何一条 ✗（缺文件、哈希不符、目标已存在、落在禁止目录）→ **整体拒绝，不动任何东西**。
3. **顺序固定**（上面表里的顺序不是随意排的）：拷模式"先还原工程、再删副本"；搬模式"先搬回原件、再还原工程"。
   两种顺序都保证**任何一个中间态都不会出现"工程指向不存在的文件"**。
4. **不做"尽力而为"**：动到一半失败就**停下、把已经做了什么如实打出来**，不自动回滚（回滚本身也会失败，越滚越乱）。
5. **回读核对（撤销后必须做，跟写盘一样严）**：
   · 工程文件：**长度 + 哈希**与记录里的"改前"一致（最强判据：逐字节回到改前）；
   · 记录里每条路径**重新在盘上存在**；
   · 记录里每条"产物"**都不再存在**；每条"原件"**都回到原位且哈希一致**；
   · 数一遍：副本删了几个 / 原件搬回几个，与记录对得上。
6. **用完即弃**：撤销成功就把记录标 `已撤销`，再点就提示"没有可撤销的记录"（只撤一步）。
7. **禁止目录一律拒绝**：记录里任何路径命中 `测试效果` / `\temp\` / `\tmp\` / `%TEMP%` / `robin-⑥` →
   **整体拒绝**（跟写盘那条硬闸同一套判据）。

### 4. 界面

- 位置：⑥ 面板**顶部**（① 导入工程那张卡里，扫描按钮旁边）一个次要按钮「**撤销上一次处理**」，
  下面一行小字：「上一次：18:23 搬运（拷）→ `E:\C test\达到`」。
- **没有记录时**：按钮禁用 + 一行「没有可撤销的记录」。**不许猜、不许"尽力还原"**。
- 点它 → **先出表**（第 3 条第 1 点那张表，走侧栏提示而不是弹窗）→ 底部一个「确认撤销」。
- 撤销完：一句话 + 回读数字（工程文件哈希/长度回到改前、副本删了 N 个 / 原件搬回 N 个）。
- **撤销失败**：按本工程规矩写在**侧栏**，写清卡在哪一条、已经动了什么。

### 5. 明确不做（免得越做越乱）

- **不做任意历史回滚**（不做时间轴、不做"回到某一天"）。只做"上一次"，要不要留 3 步栈请用户拍。
- **不自动清理用户的其它副本**：像 `达到\模型\`、`达到\特效\` 这种**不在记录里**的目录，一个都不碰。
- **不删"整棵目录"**：只删记录里列出的文件；目录只有在**空了**之后才收掉。
- **不改素材**：库里 `…\UserFile\` 那种原始素材永远只读（撤销也不会往里写）。
- **救不了已经发生的那次**（§一.5）：没有记录就没有依据。这次只能靠库里那两份 2023 的 `.bak` 手工收拾
  （要不要我出一份"手工收拾这次的步骤清单"？—— 那是另一件事，也要用户点头）。

### 6. 顺带的（另一条，不属于本方案，但同源）

现场这个错的一半原因是**输入本来就会指错**：目标目录 `E:\C test\达到\盛大的` 落在"根"
`E:\C test`（或 `E:\deepseek-harness`）**里面**，于是算出来的路径必然多套一段。
**撤销是兜底，不该当常规出路** —— 建议同时做「目标落在根里面 / 目标就是某个旧根的祖先」直接拦下来并说清。
要不要一起排，请用户拍。
