一、把 Channels.svelte 的面板分支链拆成模块

Strong in-process 接缝已经在 registry 里了 
src/lib/modules/channels/Channels.svelte        1859 行  ← 7 个分区挤在一个文件里
src/lib/modules/channels/{Extract,Pipeline,AdjustEditor,
  LayerStack,MaskEditor,SourcePick}.svelte     88–543 行
src/lib/modules/registry.ts                       面板表，已有 component 字段
痛点
加一个分区要往 1142–1624 的分支链里插一段，而七个分区共享同一份组件状态——想看懂其中一个，得把整条链读完。
改法
每个分区做成自己的模块，注册进 registry.ts 已有的 panels[].component；链子上只留一个 <PanelComp />。
  • locality：改一个分区只碰它自己那一个文件
  • leverage：registry 是一条接缝，N 个分区共用
  • 接口收缩到 { panelId }
  • 删除测试：不通过——它是真模块，不是直通壳
这条接缝**已经存在了一半**：registry.ts 里 Extract 和 Pipeline 早就作为独立模块注册在 channels 底下。 剩下五个还留在链子上，所以现在两种写法并存，读的人得先判断"这个分区属于哪种"。

二、当前分区只留一个属主

Strong in-process 已复现的真实 bug 
src/routes/tools/[id]/+page.svelte   337 行 · 所有模块共用
  let cur = $state('')                    ← 当前分区的第一个属主
  $effect(() => { … page.url … cur = next })   ← 校正两者
  function pickPanel(pid) { cur = pid; … }     ← 第二个属主
痛点
同一个事实（当前分区）有两份状态，靠一个 $effect 互相校正；两边不一致时它会把用户刚点的东西改回去。
改法
URL 做唯一属主，cur 改成 $derived，点击只负责 goto，校正 effect 删掉。
  • locality：分区归属的 bug 不再存在
  • 少一份状态、少一个 effect
  • 不可能再出现两边打架
这一条**已经修了**——但修的是症状（把原生 history.replaceState 换成 SvelteKit 的 goto）。 两个属主的形状还在，同样的 bug 还能从别的路径长出来。

痛点
这两个模块的数学已经抽到 ops.ts（接口位置是对的），但没有任何对着真实素材的判据，改动只能靠肉眼。
改法
照 tmp/dump-ramps.mjs 的样子把真实素材导成基准，跑真代码断言。
  • leverage：一份基准护住整个模块
  • 接口已经是可测形状
  • 素材缺口会变成显式失败

先做哪个

第一条：把 Channels.svelte 的面板分支链拆成模块

channels 是九个模块里最大的一处面——3972 行 svelte 挤在 7 个文件里，而 registry.ts 里那条接缝**已经存在了一半** （Extract / Pipeline 早就是独立模块）。把剩下的并过去不是在开新路，是把已经走通的那条走完。 收益是 locality：每个分区一个模块，它自己的 bug 只可能在它自己那个文件里。

第二条可以紧随其后——它只有 337 行，改动面小，而且现在的修法是治症状，属主的形状没动。
