这条是**全局规则**，管所有工作区（① 日文 / ② 调色 / ③ Ray / ④ msToon / ⑤ 绝区零贴图合成 / ⑥ 工程迁移 /
⑦ 贴图通道 / ⑧ 养乐多）。

## 一、版面：四个区，每区只干一件事

```
┌───────────────────────────────────────────────────────────────┐
│ 顶栏：这一页是干什么的（一句话）+ 主操作按钮（唯一的主按钮）        │
├──────────────┬──────────────────────────────┬─────────────────┤
│ 左：素材       │ 中：结果                       │ 右：参数          │
│ 放什么进去      │ 看到什么（预览/表/清单）         │ 调什么（只放控件）  │
│ 只放“槽位”     │ 主按钮的产物在这里              │ 不放解释文字       │
├──────────────┴──────────────────────────────┴─────────────────┤
│ 底栏（固定）：这一步要写什么 · 影响几个文件 ────[ 执行 / 写盘 ]    │
└───────────────────────────────────────────────────────────────┘
```

**分工一句话**：**左放素材、中看结果、右调参数、底执行**。任何一块都不许越界干别人的事。

## 二、右栏：**只放控件**

- **只出现**：输入框、滑杆、开关、下拉、色块、标签切换。
- **不出现**：成段的说明、原理、注意事项、教程、免责声明、历史记录、日志。
- 每个控件带一句**不超过 8 个字的标签**（如「曝光」「笔刷大小」）；需要解释的，用 **`?` 图标**，
  鼠标停上去/点一下才展开一小段（默认收起）。
- **长说明集中放两个地方**：① 顶栏那个 `?`（这一页是干什么的）；② 页面最底部一个**默认折叠**的
  「说明与注意事项」。右栏里一律不留。

## 三、分类明确

- 一个工作区**只有一个主题**；主题之外的东西属于别的模块（例如 SDF 已并入 ④，不再占 ⑤ 的位置）。
- 右栏参数按**模式标签**分（已定：固定板块 + 标签切换，按宽度自动换列），**一屏一个模式**，
  不再"一长条往下堆"。
- 每个模式里的参数**按用途分组**（例：调色＝基本 / 曲线 / 色轮 / HSL / LOG / 变形 / LUT），
  组内不超过 **8 个控件**，多了再拆一个标签。

## 四、新手友好（可检验的四条）

1. **一步一个动作**：每个界面最多**一个主按钮**（其余都是 ghost/次级）。
2. **能自动就自动**：默认把能推断的填好（旧根、新根、尺寸、编码、模板），**人只改个别条目**。
3. **默认值合理**：每个参数都有能直接用的默认值，界面打开就能按主按钮出结果。
4. **不让人猜**：任何"我替你做了决定"的地方，**当场一句话说清做了什么**（不是解释原理，是说结果）。

## 七、小模块分工（**上一版漏了，这里补上**）

四区版面只解决"一页之内怎么摆"，没解决"**一个模块里有十几个小功能，谁管什么**"。
补三条，管**模块之间**与**模块之内**：

### 7.1 模块之间：一个模块一句话职责，重叠的必须划清或合并

- 每个模块的职责写成**一句话**，写进注册表描述与顶栏；**两句话语义重叠就是设计错**。
  现状里已经有这种重叠：**③ Ray 编辑器** 与 **⑧ 养乐多** 都叫"渲染联动"（都在"选模型 → 挂特效 → 写盘"），
  差别其实很清楚：**Ray 管"改 ray.conf 与 .fx 里的参数"**，**养乐多管"按 PMM 材质名生成 .fx"** ——
  这两句要写进各自顶栏，让新手一看就知道该进哪个。
- **功能重复实现必须并成一处**（去重清单里还挂着的几条：星铁阶梯两份、两套 FaceSDF、
  四条"取某一路当灰度"、三套"阶梯→图"引擎）。**界面分工再清楚，底下两份实现也会漂开。**

### 7.2 模块之内：分区只分两种角色

- **主线**（新手只走这条，**每个模块最多 1 条**）：从素材到结果的最短路径，默认落在这里。
- **工具**（选修）：一次性、进阶、排查用的分区，**收进分区条右端的「更多工具」**，
  默认不占地方，但**名字要好找**。
- 分区名 = **动词 + 对象**（"通道提取""按尺寸重造一张"这种），**不许出现"杂项/其他/高级"**。
- **分区之间不许功能重叠**；一条能从主线直通的结果，不许再开一个分区重做一遍。

### 7.3 分区之间共享的东西放模块级

- **源图/素材、输出目录、约定（通道含义）、导出后缀**这些**整个模块共用的输入**，
  放在**分区条上方或底部条**（模块级），**切分区不丢、不用重填**。
- 每个分区打开都**继承同一套骨架**：左素材 / 中结果 / 右参数 / 底执行 —— **切分区时位置不变、只换内容**，
  新手不用重新学一遍。
- 一个模块的分区**上限 6 个**；超了就是该拆成两个模块，或者把工具类收进「更多工具」。

### 7.4 "我该用哪个"要在界面上有答案

- 顶栏一句话写**这一页的职责**；分区条里**主线排第一**；
- 工具类分区在「更多工具」里**各带半句"什么时候用它"**（不是原理，是场景）；
- 新手从任何模块进来，**只按一个主按钮**就能出结果，不需要先搞清所有分区。


## 八、右栏不许把工作区挤窄（**用户实测报的："右栏占空间了工作区很挤"**）

- **中区优先**：栅格 `minmax(0, 1fr) <右栏>`，右栏**宽度有上限**，**默认不要 21rem/24rem 那么宽**。
  用户屏 2560×1600@150%（CSS 视口 1707 宽）、扣掉侧边导航只剩约 1370 ——
  **右栏每多 100px，中区就少 100px**。
- **右栏可收起**：顶栏一个「收起参数」按钮（跟已有「宽预览」一个思路），收起后中区吃满；状态记住。
- **宽度可拖**：右栏左边缘给拖拽把手，12rem–28rem 可调，宽度记忆。
- **窄屏自动**：视口不够时右栏收到最窄或挪到下方，不许把中区压到看不清。
- **三列模块（养乐多等）**：左栏也必须**可收起且默认窄**；左+右相加不许超过视口一半。
- **检验**：任何工作区在 **1707×1067**（用户视口）下，**中区可用宽度不得低于 900px**。

## 十、锁死目标：工作区不拥挤 · 分工明确 · 主次明确 · 排版不崩坏

用户 2026-09-22 原话："**锁死目标，工作区必须不能拥挤，分工明确，主次明确，排版不崩坏**"。
这四条**是验收标准，不再是原则**；每条都要**可机检**，不许拿"我看着行"当通过。

### 10.1 不拥挤（可量）
- 在 **1707×1067**（用户视口）下，**中区可用宽度 ≥ 900px**；
- **任何面板不许出现横向滚动**（`scrollWidth > clientWidth` 即失败）；
- 右栏宽度 ≤ **20rem**（默认），左栏（三列模块）默认窄，**左+右相加 ≤ 视口一半**。

### 10.2 分工明确（可量）
- 四区各司其职：**左素材 / 中结果 / 右参数 / 底执行**；**右栏里不许出现成段说明**（只有控件与 `?`）；
- 分区只有两种角色：**主线（排第一，最多 1 条）** 与 **「更多工具」**（其余全收进去）。

### 10.3 主次明确（可量）
- **每页 `btn--primary` 恰好 1 个**（0 个或多于 1 个都算失败）；
  **数的是"用户在页面上看得见的那些"**，不是 DOM 里那几个 —— 收起状态下停在视口外的、
  被祖先 `display:none` / `visibility:hidden` / `opacity:0` 盖住的、`<details>` 没打开的，
  **都不算**（口径与白名单见 **§十六**）；
- **主按钮待的地方是主区最后一行那条主操作条（`.wb__acts`）**，不许画进 `.wb__side`
  参数抽屉 —— 抽屉默认收起，按钮跟着一起看不见，用户进页面就没有可点的那一下；
- 主线分区里**必有一个能做完整件事的路径**（不需要先去工具区）。

### 10.4 排版不崩坏（可量）
- **没有元素重叠**（同一容器内兄弟元素两两求交，面积 > 0 即失败）；
- **没有溢出容器**（`getBoundingClientRect()` 超出最近滚动祖先的可见区域即失败）；
- 长路径**换行显示**（`wrap-css` 那 14 条护栏继续有效）；
- 窄屏（<1280px）自动降级为**一列**，不许挤成条。

### 10.5 怎么检（**不许人眼当唯一依据**）
写一个**自动排布体检**（CDP 连到带 `--remote-debugging-port` 起的实例，逐个模块/分区跑）：
量上面每一条，输出**逐页表格**（中区宽度 / 横向滚动 / 重叠数 / 溢出数 / primary 按钮数 / 右栏宽度）。
**任何一项不过就是不过**，改完重跑，直到全绿；每次改界面后都跑一遍，当回归用。
（开窗这件事由用户点头后做；脚本与量法先写好。）


## 十一、参数**不占宽度**（**否定 §八 的"收窄/可收起"** —— 用户明确否掉）

用户原话："**别死都护着右栏了，占空间还不承认**"。
→ **答案不是"更窄的右栏"，也不是"可收起的右栏"** —— **中区永远吃满可用宽度，参数不占布局宽度**。

- **中区＝整幅**：除了侧边导航，**没有别的列在吃宽度**；
- **参数＝浮层抽屉**：从右侧滑出、**盖在中区之上**、**默认收起**（收起＝完全不占地方）；
  点顶栏「参数」才滑出，宽度 ≤ **18rem**，**浮在上面、不挤压中区**；
- **想边看预览边调** → 用户自己点「**钉住**」才占宽（≤18rem），**默认不钉**；
- **素材槽位也照此**：做成**顶部一条**或**可滑出的浮层**，不占宽度；
- **检验（替代 §八 的 900px 那条）**：1707×1067 下**中区宽度 = 视口 − 侧边导航宽**（误差 ±16px）；
  **任何面板不许横向滚动**。

### 10.6 请你拍的三件（§10 落地前）

2. **主按钮**：每个界面只留**一个**主按钮（写盘/执行），其余降级为次级按钮 —— 同意吗？
3. **先拿 ⑥ 开刀**做一页样板给你看，然后再铺其余页 —— 还是先做你更常用的一页？

## 十三、自动排布体检真的跑起来了（2026-09-22 晚）—— 数字在这里

**脚本**：`tools\ui-audit.mjs`。它连到带 `--remote-debugging-port` 的实例，**自己把视口设成 1707×1067**，
并从页面里**自己发现模块与分区**（左导航的 `/tools/<id>`、分区条的 `?panel=`），逐页量六个数、出表格、
**任何一项不过就退出码非 0**。

```powershell
# 应用窗口（开窗那一次由用户来）
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = '--remote-debugging-port=9333'
pnpm tauri dev
node tools/ui-audit.mjs --all

# 也可以对着同一个前端在无头浏览器里量（布局一样，不用开应用窗口）
pnpm dev
chrome --headless=new --remote-debugging-port=9400 --window-size=1707,1067 http://127.0.0.1:1420/
$env:CDP_PORT='9400'; $env:AUDIT_BASE='http://127.0.0.1:1420/'
node tools/ui-audit.mjs --all
```

环境变量：`CDP_PORT`（默认 9333）、`AUDIT_W`/`AUDIT_H`（默认 1707×1067）、`AUDIT_ONLY=路由关键词`、
`AUDIT_URL=单页路由`、`AUDIT_PANELS`（每页最多量几个分区）。

**判据（已按 §十一 改过；§八 的"收窄/可收起"作废）**：
中区＝整幅（**中区右边不留空** ≤32px，也就是只剩页面自己 16×2 的留白）、**非浮层的列在吃宽度 = 0**、
**抽屉默认是收起的**、横向滚动 = 0、重叠 = 0、溢出 = 0（吸附/浮层元素压住内容是规范要求的，不算）、
`btn--primary` = 1。另外照报**中区 vs 视口−左导航**这条算式。
**另外两条 2026-09-23 加/改的见 §十五**：抽屉收没收起**看 `<html>` 上的 `.side-open`**（不再拿"停在视口外"当收起）、
**有 `.wb__side` 却没有能打开它的控件 → FAIL**；分区发现改成认分区条的 `<button>`。
**还没有工作区版面（`.wb`）的页记 `n/a`**，算进 §五 的铺开清单，不算 FAIL。

**中区 1339 = 1371（视口−导航）− 32（页面左右各 16px 留白）** ✓ —— 用户要的"中区＝整幅"就是这条。

**结论**：**⑥ 全绿**。其余不过的页就是 §五 的铺开清单 —— 3 页一个主按钮都没有；
`ilm/mstoon/ikclut` 还是老右栏，它们**现在已经不占宽度了**（`.wb__side` 全局改成了浮层抽屉，
中区都是 1339 = 整幅），但抽屉里的内容自己超出 148px，要按 §十一 各页清一遍。
**这些数字是量出来的，不是我看着说的。**

**⑥ 上被测出来的三个真问题（都修了）**：
1. 底栏原来放在 `.wb` 栅格**里面**、还带 `grid-column: 1/-1` → 它占掉一整行，把右栏挤到下一行的第一列，

## 十六、§10.3 的口径改对了：**只数"用户在页面上看得见的"**（2026-09-23）

### 16.1 口径（用户拍板）

判据是"**用户在页面上只看到一个主按钮**"，不是"DOM 里只有一个"。所以体检
（`tools\ui-audit.mjs`）计数时，下面这些**都不算**：

- **收起状态下停在视口外的** —— 参数抽屉 `.wb__side` 默认收起，被 `translateX(100% + 16px)`
  移到视口右边外面（实测 `left≈1715`，视口 1707），里面的主按钮用户看不见；
- 祖先 `display:none` / `visibility:hidden` / `opacity:0` 的；
- `<details>` 没打开的；矩形是 0 的；以及滚出视口上下两端的。

**同一个页面上真的同时看得见两个** → 次要动作降 `btn--ghost` / `btn--sm`。

### 16.2 新口径下露出来的真问题：主按钮藏在参数抽屉里

按新口径**逐分区**复测（`AUDIT_PANELS=12`），**16 行从"1"掉成"0"**：

| 页 | 分区 |
| --- | --- |
| `/tools/channels` | 默认（games）/ region / games / extract / layers / adjust / blend / split / merge / swizzle |
| `/tools/ilm` | pack（默认） |
| `/tools/ramp` | export / sample |
| `/tools/mstoon` | pack（默认） |
| `/tools/ikclut` | clut（默认）/ blend / export |

**根因**：这些页面把**唯一那个主按钮**画在 `.wb__side` 参数抽屉里，而抽屉默认收起 ——
用户进了页面，**一个可点的主操作都没有**。这比"多了两个"更糟：§十一 把参数挪出布局是对的，
**但主按钮不能跟着一起挪进抽屉**。

### 16.3 改法：`.wb__acts` —— 主区最后一行那条主操作条

- 新加一个全局件（`src\styles\wb.css` 的 `.wb__acts`）：主区（`.wb__main`）最后一行、
  吸底的横向条，里面放这一页那**唯一**主按钮（次级动作是 `btn--ghost` 陪着）；
- 各页把原来画在抽屉里的那颗主按钮**搬到这条里** —— 不是新造按钮，就是原来那一颗，
  连 `disabled` 条件一起搬；抽屉只留参数；
- 抽屉里跟主按钮**同一件事**的第二颗主按钮一律降 `btn--ghost`
  （`extract` 的「导出光泽」、`layers` 的「恢复」）；
- 按钮**一直在**（没载入图时是 `disabled`），不是"载入之后才出现" ——
  那是状态，不是这一页的属性，跟 ⑥ 底栏那个主按钮一个写法。

改的文件：`src\styles\wb.css`（新增 `.wb__acts`）、`Channels.svelte`（6 个分区）、

用户原话："**还需要为了我的需求进行收纳折叠展开设计来满足**"。
→ 工作区里的东西**不能全摊开**：默认只露主线，其余**收进可折叠的区块**，需要时展开。

**三级收纳（只有这三层，不许更深）**
1. **主线（常开）**：这一页最短路径要用的东西 —— 素材、结果、**唯一主按钮**（底栏）。
2. **区块卡（可折叠）**：每个区块是一件事（例：`路径指向了别的位置`、`逐条指定`、`找不到的让工具去搜`）。
   - 标题 = **动词短语**；标题右侧显示**关键读数**（例：`逐条指定 · 模型 12 / 附件 3 / 没落定 0`）——
     **收起也能看出这条要不要展开**，不靠记忆；
   - **展开态按页 + 按区块记忆**（下次进来照旧）；
   - 首次进入的默认：主线 + **有未落定/有问题的区块自动展开**，其余收起。
3. **「更多工具」（默认收起）**：一次性、进阶、排查类动作全在这里（重置工程 / 按目录名整批改 / 把文件搬过去 / 找回挪走的文件）。

**规则**
- **一屏主线控件 ≤ 8 个**；超了就必须收进区块。
- **折叠不许藏主按钮的必填项**：主按钮必需的输入（例如打包的输出目录）**必须在主区看得见**，不许塞进收起的区块或抽屉。
- **参数抽屉（§十一）与区块折叠是两套**：抽屉放"调什么"，区块放"这一页的哪件事"，别互相嵌套。
- 折叠/展开**不弹窗、不跳页**，就地开合；**动效只做位移**（守本工程规矩：不许过冲）。

### 19.1 写盘条**永远在最上层、不许被任何底栏挡住**（B5）

- 应用状态栏是 `position: fixed; bottom: 0`、高 `--status-h`（30px）、层级 `--z-status`（60）；
- **底栏 / 主操作条（`.foot` / `.wb__acts`）**：`bottom: var(--status-h)` + `z-index: calc(var(--z-status) + 5)`。
  原来写 `bottom: 0; z-index: 2~3` —— 下半截正好压在状态栏底下，「打包到输出目录」点不到（用户实测）。
- **体检判据**（`tools\ui-audit.mjs` 的「点得到」列）：主按钮中心 `elementFromPoint` 必须命中它自己或它的后代。
  1707×1067 全站实测 ok；把底栏临时拉回 `bottom: 0` 就会报被 `sb glass` 挡住（判据是活的）。

### 19.2 折叠卡：**收起就真的收起**（B7 顺带查出来的）

`<details>` 收起靠的是 UA 样式（`display:none` 那些非 summary 子节点），而 **UA 规则输给作者规则** ——
给折叠正文设过 `display:flex` 的卡（`.fold__body` / `.more__body`）**看着收起、正文一直画着**。
`wb.css` 里补了 `details:not([open]) > *:not(summary) { display: none !important; }`。
**新写折叠卡时不用再自己管这条**；但**别指望"收起"能藏住主按钮的必填项**（§十八 那条仍然成立）。
