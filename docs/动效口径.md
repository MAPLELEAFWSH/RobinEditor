# 动效口径

全站动效只有两套数字来源，都在 `src/styles/tokens.css` 里。**不要在组件里就地写时长或曲线。**

之前按 notitle PV 推了一套（180/420ms + `cubic-bezier(.16,1,.3,1)`），
还自己加了三个过冲曲线。后来按你的要求「动效重申模仿 RyuChan / witchcat / lin-xin / Mizuki」，
把这四家重新量了一遍，结论是**我原来那套和四家都不搭**，已经全部换掉。

---

## 一、缓动只有两条

四家参考里**没有任何过冲缓动**（没有 back / elastic / spring）。
Mizuki 整站只用一条曲线，离场单独换一条：

```css
--ease-std:  cubic-bezier(0.4, 0, 0.2, 1);   /* 全站主用 */
--ease-exit: cubic-bezier(0.4, 0, 0.6, 1);   /* 离场：加速收走 */
--ease-slow: cubic-bezier(0.65, 0, 0.35, 1); /* 只有超大位移和背景漂移用 */
```

`(0.4, 0, 0.2, 1)` 同时也是 Tailwind 的默认缓动 —— witchcat / lin-xin / RyuChan
三家的交互几乎全是这个值（实测 `transition: color 0.2s` 这类写法吃的就是它）。

**为什么不要过冲**：它们的"力量感"来自**按下瞬间缩到 0.9**和**短时长**，
不是靠曲线越界。越界在工具类界面上会显得飘，和其他三家的语言也不一致。

## 二、时长阶梯

按元素大小排，全部取自参考的实测值：

| 令牌 | 值 | 用途 | 出处 |
|---|---|---|---|
| `--t-press` | **75ms** | 按下那一下 | Mizuki 主题按钮 `::before` |
| `--t-micro` | **200ms** | 颜色、背景、位移的微交互 | witchcat / lin-xin 全站 `0.2s` |
| `--t-btn` | 250ms | 按钮 | RyuChan `--animation-btn` |
| `--t-exit` | 250ms | 离场 | Mizuki `.animate-leave` |
| `--t-nav` | 280ms | 导航栏 | Mizuki `.navbar-animate` |
| `--t-side` | 300ms | 侧栏、面板展开 | Mizuki `.sidebar-animate` |
| `--t-enter` | 350ms | 通用淡入 | Mizuki `.enhanced-fade-in` |
| `--t-card` | 400ms | 卡片进场 | Mizuki `.card-animate` |
| `--t-reveal` | 1000ms | 背景层透明度 | lin-xin |
| `--t-drift` | 8.6s | 背景漂移 | lin-xin |

**离场比进场快**（250 vs 350/400），而且换加速曲线。
进场慢一点看得清，离场拖沓就会显得卡。

## 三、位移与缩放

| 令牌 | 值 | 用在哪 | 出处 |
|---|---|---|---|
| `--lift-btn` | **-1px** | 按钮悬停 | witchcat `.btn-regular:hover` / RyuChan |
| `--lift-nav` | -2px | 导航项、分段按钮 | Mizuki `.button-enhance:hover` |
| `--lift-card` | **-4px** | 卡片悬停 | witchcat 卡片 / RyuChan `-translate-y-1` |
| `--press-scale` | **0.9** | 按下 | witchcat `.btn-regular:active` / Mizuki `active:scale-90` |
| `--press-scale-soft` | 0.95 | 按钮按下 | RyuChan `--btn-focus-scale` |
| `--rise-card` | 2rem | 卡片进场位移 | Mizuki |
| `--rise-soft` | 1rem | 正文 / 页脚进场位移 | Mizuki |
| `--enter-scale` | 0.95 | 卡片进场缩放 | Mizuki |
| `--enter-scale-soft` | 0.98 | 通用淡入缩放 | Mizuki |
| `--stagger` | 60ms | 批次错峰 | 一批 ≤5 项 |

进场组合永远是 **透明度 + 位移 + 缩放**三个一起动，不是只淡入。
类名 `.rise`（重）和 `.rise--soft`（轻），错峰用 `style="--i:1"` 递增。

## 四、选中与悬浮（侧栏）

这块单独说过，照着重做过：

- **导航项本身是透明的**，悬停只换 `background-color` 和字色，200ms，行不做位移。
  （witchcat `.sidebar-item-theme { transition: background-color .2s }`）
- **选中靠一条独立的滑动指示条**。整个侧栏只有一条 `.ind`，
  换项时它 `transform: translate()` 滑过去 —— 不是各自亮各自的背景。
  （lin-xin 的 `.nav-indicator`，实测 56×4 的绝对定位条）
- 侧栏整体进场是 `translateX(-2rem)` + 淡入，300ms。（Mizuki `.sidebar-animate`）
- 之前那版是「左侧竖条 + 行内 translateX + 点击涟漪」，通用模板的写法，
  和四家的语言都不搭，已经删掉了。

实测换项时指示条位置：`124 → 125 → 149 → 221 → 277 → 304 → 317 → 320 → 321`，
315ms 内平滑滑到位。

## 五、主题切换：必须 0ms 生效

**这是被专门点出来的问题。** 原来用 View Transitions：截整页快照 →
等 `ready` → 再跑 450ms 圆擦除。点下去到画面动，中间隔着两段等待，
手感就是卡一下（1707×876、dpr 1.5 的快照约 2560×1314 一张位图）。

四家都不这么做。Mizuki 的 `ThemeSwitch.svelte` 是**立即切**，CSS 里专门写：

```css
.theme-switch-btn::before {
  transition: transform 75ms ease-out, background-color 0ms !important;
}
```

`background-color 0ms` 的意思就是：颜色变化不允许有过渡，必须当帧生效。
它只给图标 300ms 的 `rotate(-90deg) → 0` + 淡入淡出，按钮按下 `active:scale-90`。

改后实测（`src/lib/theme.ts`）：

```
属性与 CSS 变量在点击处理函数内改完   3.5ms
首帧画出新主题                        3.8ms
```

做法：`toggleTheme()` 直接改 `prefs.theme` 然后 `apply()`；
模板里两个图标叠着，靠 `.switch__slot.on` 切 `opacity` + `rotate`，300ms。

## 六、性能红线

1. **只动 `transform` / `opacity` / 颜色**。不要动画 `width`/`height`/`top`/`margin`
   （侧栏收起和二级展开是例外，它们必须走布局，但都是低频的用户操作）。
2. **全站一条 rAF 循环**（`src/lib/perf.svelte.ts`），没人订阅自动停，页面隐藏停机。
3. **指针跟随、涟漪：JS 只算位置，动画交给 CSS**。`pointermove` 逐帧节流。
4. **全屏图上默认不挂 `filter`**。实测滚动时 `blur(6px)` 让帧时间从 4.8ms 涨到 7.4ms（+54%）。
   关的时候 CSS 里一条 `filter` 都不写 —— `blur(0px)` 同样会触发光栅化。
5. **卡片不挂 `backdrop-filter`**。一页十几张卡，每张一次背景模糊就是掉帧大户。
6. **尾栏帧率可关**。关掉之后采样链路完全静默，页面能真正空闲。

实测（1707×876，dpr 1.5，滚动 + 移指针）：

| 场景 | 帧时间中位 | p95 | 超 16.7ms 的帧 |
|---|---|---|---|
| 空闲 | 4.5ms | 8.3ms | 0 |
| 滚动 | 4.2ms | 8.4ms | 0 |
| 悬停（306 次 pointermove） | 4.2ms | 6.4ms | 0 |
| 侧栏换项导航 ×4 | 4.2ms | 8.4ms | 0 |

## 七、动效档位

设置面板里可选 **关 / 轻 / 全**（`html[data-motion]`），系统
`prefers-reduced-motion: reduce` 也一并尊重。

- **关**：只留颜色和透明度，位移缩放全部去掉，涟漪不挂
- **轻**：保留位移，收掉缩放（`--lift-*` 归零、`--press-scale` 归 1）

**新加的动效必须能在这两档下退化干净**，别写死动画。
