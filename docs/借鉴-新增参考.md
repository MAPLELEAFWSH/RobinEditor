## 0. 元素手账 —— 可调参数与动效（最重要的一份）

路径：`E:\PythonProject\元素手账\网页版\`

这个项目和本工具是同一路数：**一个 `--element-hue` 派生全站颜色**，
`--element: oklch(0.70 0.14 var(--element-hue))` 和我们原来的 `--primary` 一模一样。
所以它的参数面板可以整套照搬，不用翻译。

### 它的设置面板（`#settingPanel`）一共七项

| 参数 | 控件 | 取值范围 | 落到哪个变量 |
|---|---|---|---|
| 主题色相 | range | 0–360 | `--element-hue` |
| 壁纸模式 | 分段 | 横幅 / 全屏 / 透明 / 无 | 切 `body` 上的 class |
| 卡片描边 | 分段 | 关 / 开 | 边框宽度 |
| 壁纸透明度 | range | 0–100 | `--cover-veil`（÷100） |
| 卡片透明 | range | 0–100 | `--paper-card-opacity`（÷100） |
| 壁纸柔化 | 分段 | 关 / 开 | `--cover-soften` |
| 氛围特效 | 开关组 | 樱花 / 萤火 / 弹幕 / 涟漪 | canvas 图层 |

**最值得学的一条**：它的分隔线、次要文字用的是**中性 rgba**，不掺色相；
只有主色、纸面、印章色走 `--element-hue`。这正好解释了本项目之前的"配色冲突"：
我们的 `--card-border` 写的是 `rgba(179,196,214,.45)`、`--card-shadow` 是
`rgba(112,148,193,.13)` —— 冷蓝的固定值。色相一拖到橙色，边框和阴影还是蓝的，
跟主色打架。已经按它的分法改成 `oklch(0.28 0.02 var(--hue) / 0.13)`，跟着色相走。

它连注释都写了对比度的账：`--stamp-ink` 原本取 `oklch(0.55 0.12)`，
压在自己的 `--stamp-bg` 上只有 4.05:1，过不了 WCAG AA，所以降到 0.50（≈4.94:1）。

### 主题切换的圆擦除

```js

  var r = themeBtn.getBoundingClientRect();
  var x = r.left + r.width / 2, y = r.top + r.height / 2;
  var end = Math.hypot(Math.max(x, innerWidth - x), Math.max(y, innerHeight - y));
  document.documentElement.animate(

    { duration: 450, easing: 'ease-in-out', pseudoElement: '::view-transition-new(root)' }

```

从按钮处扩散一个圆把新主题擦过去，450ms。已照搬到 `src/lib/theme.ts`。

```css

::view-transition-old(root) { z-index: 1; }
::view-transition-new(root) { z-index: 2; }
```

### 壁纸轮播：交叉淡入的关键在 visibility 的时机

它 5 秒换一张，靠 `img.on` 类切换。真正的坑在 CSS：

```css
#wallpaper img {
  opacity: 0; visibility: hidden;
  transition: opacity 1.2s ease, visibility 0s linear 1.2s;   /* ← 延迟等于淡出时长 */
}
#wallpaper img.on { opacity: var(--cover-veil); visibility: visible; transition-delay: 0s; }
```

`visibility` 是**离散**属性、不参与过渡。只写 `transition: opacity` 的话，
摘掉 `.on` 的当帧 visibility 就变 hidden，旧图直接消失 —— 看到的是"啪一下切掉 +
新图淡入"，而不是两张叠着化过去。给 visibility 一个和 opacity 等长的延迟，
它在淡出**结束之后**才隐藏，同时新图那条延迟为 0、淡入一开始就可见。

已照搬到 `src/components/Backdrop.svelte`，浏览器实测过渡帧：
`dawn:0.78 tea*:0.78` → `dawn:0.03 tea*:0.78` → `dawn:0.00 tea*:0.78`，
两张确实同时可见。

### 全屏图上的 filter 是真贵

它专门写了注释：桌面版实测（Intel 核显、dpr 1.5、窗口 1426×883 → 光栅 2139×1325），
`filter: blur()` 让帧时间中位数从 **4.3ms 涨到 12.4ms**，p95 也跟着抖。
而 1px 的模糊在照片上肉眼几乎看不出来。所以它的做法是：默认不挂 filter，
想要柔化质感才在设置里开。

本机实测（1707×876、dpr 1.5、滚动中）：

| 壁纸柔化 | 帧时间 | fps |
|---|---|---|
| 关（默认） | 4.8 ms | 209 |
| 开 `blur(6px)` | 7.4 ms | 135 |

**+54%**。和它的结论一致，所以默认关，并在面板里写明原因。
（关的时候 CSS 里**一条 filter 都不写** —— 写 `blur(0px)` 同样会触发一遍光栅化。）

### 帧调度和性能读数

它的 `Raf` 调度器（`enhance.js`）解决了三个问题：

```js
const Raf = (() => {
  const subs = new Set();
  let running = false, paused = document.hidden;
  const stats = { frames: 0, jsTotal: 0, jsMax: 0, delivered: 0 };
  function loop(now) {
    if (paused || subs.size === 0) { running = false; return; }   // ← 没人订阅就停
    stats.frames++;
    const t0 = performance.now();
    for (const fn of Array.from(subs)) { try { fn(now); } catch (e) { console.warn('[raf]', e); } }
    const cost = performance.now() - t0;                          // ← 记帧内 JS 耗时
    stats.jsTotal += cost; if (cost > stats.jsMax) stats.jsMax = cost;
    requestAnimationFrame(loop);
  }
  ...
})();
```

原名注释写得很直白：*"原实现有 3 个各自独立的 rAF 循环，全部无条件每帧空转。
这里合并成单循环 + 按可见性挂载，页面隐藏时整体停机。"*
还有一句关于帧率显示的：*"原来这里是无条件 Raf.add，也就是为了显示一个数字，
让整页永远每帧都醒着 —— 页面因此永远进不了空闲状态。"*
它改成每 3 秒采样 30 帧、采完立刻摘订阅。

已照搬到 `src/lib/perf.svelte.ts`：单循环、`subs` 为空自动停、
`visibilitychange` 整体停机、帧内 JS 耗时按 16.7ms 预算记录、
`PerformanceObserver('longtask')` 数卡顿。`whenVisible()` 用 IntersectionObserver
让元素只在视口内才挂载。

**它的环境动效降到 30fps 用的是时间门限而不是隔帧丢弃**：

```js
if (frame._last && now - frame._last < 30) return;   // 注意：提前 return 时不更新 _l
frame._last = now;
const dt = Math.min(3, (now - (frame._l || now)) / 16.667);
frame._l = now;
```

理由写得很清楚：*"120Hz 屏上也能稳定 30fps，而不是变成 60"*，
而且跳过的时间会算进下一帧的 dt，花瓣速度不会被拖慢。这条留着，做氛围特效时用。

### 底部状态栏（尾栏）

`#mjStatus`，`position: fixed; bottom: 0; height: var(--status-h)`，
三段布局：

```
[left]  应用名 + 圆点 + 版本（桌面版/网页版）+ 当前页
[mid]   篇数 / 标签数 / 字数 / 成就进度
[right] 帧率 + 导出 + 导入 + 快捷键
```

它的注释讲了布局的连带关系：*"高度走 --status-h：右下角那串悬浮球要按它让位
（见 #floating-controls），写死两处就会各自漂移"*，还记录了实际踩到的 bug：
*"z-index 9998，于是球的下沿 6px 被状态栏盖住，看着像被切了一刀。"*
所以我们这边的悬浮球用 `bottom: calc(var(--status-h) + 1rem)`，面板再往上一层
`bottom: calc(var(--status-h) + .75rem + var(--fab-stack) + .75rem)` —— 同一组令牌算，
改尺寸不会各自漂移。

## 1. Gloss Mod Manager —— 骨架参考

本机装的是 `D:\Quark\Gloss Mod Manager\`，v1.66.2，Electron + Vue 3 + Vuetify 3。
数据目录在 `E:\Gloss\`。

### 借它的什么

**① 侧栏 + rail 的结构**

它的主界面是 `v-navigation-drawer` 配 `rail` 模式，加 `v-app-bar` 和 `v-list`。
翻它的 bundle 时 `navigation-drawer` 出现 16 次、`rail` 20 次、`v-list` 47 次。
侧栏收起来只剩一条图标带 —— 这正是本工具要的：占地方小、随时能收。
（我们实现里那个 `--rail-collapsed` 的名字就是从这来的。）

**② 侧栏内容**

一级就五项：首页、游戏、下载、设置、关于。没有二级折叠，切页面全靠顶栏。
本工具比它多一层，因为八个功能天然要分组，但**底部固定"设置 / 关于"** 这点照抄了。

**③ 备份模型（这是最值钱的一条）**

`E:\Gloss\~Backup\` 底下分两类：

```
~Backup/
  Archive/<游戏名>/backup.json     ← 被替换掉的原始文件归档
  Game/<游戏名>/backup.json        ← 原始文件快照
```

再配一份 `mod.json` 记录每个 mod 的状态：

```json
{ "id": 1, "webId": 203885, "modName": "...", "md5": "2a224c27...",
  "modVersion": "0.6.8470.31280", "isInstalled": true, "weight": 500,
  "modFiles": ["\\license.txt", "\\ModLoader\\lml.ini", ...],
  "modAuthor": "LMS", "fileName": "203885.zip", "modType": 1,
  "advanced": { "enabled": false, "data": {} } }
```

要点在四个字段：`md5`（校验）、`modFiles`（装了什么，卸载时照着删）、
`weight`（加载顺序）、`isInstalled`（状态）。
本工具的"覆盖前自动备份"按这个来：**工程清单记输入文件哈希 + 产出文件清单 + 参数快照**，
出问题能整批退回。

**④ 类型定义**

它的 mod 类型带着"安装路径 / 卸载方式 / 相对于主目录"三个属性，
见它界面上的说法：*"将打开高级设置，如果不了解请不要随意开启，否则会导致 mod 或游戏损坏"*。
对应到本工具就是**渲染包适配器**：Ray / 养乐多 / ikClut / msToon 各自一套路径规则，
载入时用特征文件认门（`ray.conf`、`mat_body.fx`……），认不到就不让存。

**⑤ 体积这件事**

官网写 V2 "体积缩减 90%"。我们走 Tauri 而不是 Electron，本身就比它小一个量级。
`TODO`：v1 打包后量一次真实安装包大小，写进关于页。

### 不借它的什么

- 不抄它的界面代码。Vue + Vuetify 那套和本项目的 Svelte 5 差得远，硬搬没意义。
- 不抄它的游戏字典（`res/EldenRingDictionary.txt` 这类，最大的一个 4.8 MB）。
  那是给游戏安装目录做路径推断用的，MMD 侧没有对应需求。
- 它带的 `aria2`、`7z` 是下载和解包用的，本工具不下载 mod，用不上。

## 3. witchcat.cn —— 侧栏条目的 token 口径

实测 `:root` + `.dark` 两套自定义属性。它和 Mizuki 是同一套做法：
**一个 `--hue` 派生全部颜色**（`--hue: 214`）。

```css
:root {
  --page-bg: oklch(0.95 0.01 var(--hue));
  --theme-card-bg: hsl(215,20%,100%);
  --theme-card-bg-90: hsla(215,20%,100%,0.9);   /* 半透明面 */
  --theme-card-bg-80: hsla(215,20%,100%,0.8);
  --theme-card-border: hsla(215,20%,100%,0.8);
  --theme-sidebar-item-bg:    hsl(215,70%,95%);  /* ← 侧栏条目 */
  --theme-sidebar-item-hover: hsl(215,70%,90%);
  --theme-tag-bg: hsl(215,70%,90%);
}
.dark {
  --page-bg: oklch(0.16 0.014 var(--hue));
  --theme-card-bg: hsl(215,20%,11%);
  --theme-sidebar-item-bg:    hsl(215,20%,15%);
  --theme-sidebar-item-hover: hsl(215,20%,20%);
  --theme-card-border: hsla(215,20%,35%,0.6);
}
```

两条可用的规律：

1. **侧栏条目单独一套 token**，不跟按钮共用。浅色下彩度高、暗色下几乎无色（20% 饱和），
   只抬亮度。本工具照这个加了 `--rail-item-bg / --rail-item-hover / --rail-item-active`。
2. **卡片可以有半透明版本**（`-90` / `-80`）给顶栏和浮层用。本工具顶栏用的就是
   `--card-bg-90` + `blur(10px)`。

圆角分布（命中次数）：`9999px`×130、`8px`×65、`16px`×19、`12px`×14、`6px`×3、`4px`×2。
**主力量是 8px 和 16px**，大圆角只给胶囊。我们现在的阶梯和这个不冲突。

它右下角挂了个 Live2D 看板娘。工具类应用不适合放这个，**不做**，记一笔备查。

## 4. blog.lin-xin.top —— 胶囊导航与滑动指示器

上次量过卡片，这次补量了导航。

```
nav.shell-nav           width 594  height 41  border-radius 999px
span.nav-indicator      56 × 4     absolute    ← 跟着当前项走的指示器
```

卡片（上次量的，一并留档）：

```

  background  color(srgb 0.1298 0.1308 0.1325 / 0.70)   ← 半透明深灰
  border      0.667px rgba(188,204,223,.12)
  box-shadow  rgba(3,8,17,.32) 0 22px 48px,
              inset 0 1px 0 rgba(255,255,255,.04)
  transition  opacity .84s cubic-bezier(.16,1,.3,1) .07s,
              transform .9s  cubic-bezier(.16,1,.3,1) .07s
```

`.84s cubic-bezier(.16,1,.3,1)` 这个缓出曲线和 notitle PV 实测出来的缓出是同一个，
互相印证。已记为 `--t-reveal: 840ms`。

标题字号：41.6px / 800 / 字距 -0.832px。负字距是它标题看起来"紧"的原因。

**指针跟随高光删了。** 当初是照 lin-xin 的 spotlight 做的：一条
`radial-gradient(220px circle at var(--mx) var(--my), ... var(--primary) 15% ...)`
叠进卡片自己的 `background-image`，指哪亮哪。看着还行，但铺到整个工作区之后
就是一片到处乱窜的蓝色光晕，很吵。整段 CSS 和 `+layout.svelte` 里那个
代理的 pointermove 一起删了，顺带把 `--accent-glow` 和所有环状彩色光晕
（侧栏游标、状态点、进度条、位置九宫格）也一并去掉。

现在悬停只留位移和阴影 —— 就是上面 RyuChan 那条"只做两件事"的路子。

**两轮顺手修掉的问题**：

1. 工具页原来写 `var(--text-2)`、`var(--line)`、`var(--card)`、`var(--font-mono)`、
   `var(--surface-2)`、`var(--shadow-sm)`，这些名字在 `tokens.css` 里**根本不存在**，
   等于全部取到初始值。已补齐。
2. `font-family` 里写着 `Zen Maru Gothic` 但没有 `@font-face`，字体根本没生效。
   已补 —— 但后来整个字体方案换了，见上面的字体小节。
3. **配色冲突的真正原因**：边框和阴影写的是固定冷蓝（`rgb(179,196,214)`、
   `rgb(112,148,193)`），不跟 `--hue` 走。已改成 `oklch(0.28 0.02 var(--hue) / α)`。
   实测：色相 230 → 40 时，卡片的 `border-top-color` 和 `box-shadow` 都跟着变成
   `oklch(0.28 0.02 40 / 0.13)`。
4. `body` 原先有底色，`position: fixed; z-index: -2` 的壁纸层会被它挡住
   （负 z-index 画在 body 背景之后）。已改成 `body { background: transparent }`，
   底色交给 `html`。

### 第三轮（不透明度分层 / 壁纸导入 / 降饱和 / 图标）

| 加的东西 | 值 / 做法 | 来自 |
|---|---|---|
| 指针跟随高光 | **删除** | — |
| `--a-card / --a-inner / --a-side / --a-bar / --a-sb / --a-panel` | 六个独立 alpha | 元素手账 `#settingPanel` 扩展到所有面 |
| `--base-card / --base-page-2 / --base-surface-2 / --base-surface-3` | 只有这几个存真色值 | 同上 |
| `src/lib/bg-store.svelte.ts` | IndexedDB `robin.bg` 存导入的壁纸 | 自用 |
| `tools/import_wallpapers.py` | 内置壁纸的亮度/遮罩批量算 | 元素手账的自适应思路 |
| `tools/crop_icon.py` | 联系人单格 → 全平台图标 | 自用 |
| `static/app-icon.png` | 界面内的 logo（256，150KB） | 自用 |

三件事的做法：

**不透明度**：原来 `--card-opacity` 全站只有 `.card` 一条规则在用，
`.card__inner` 写死 92%，侧栏顶栏尾栏走的是毛玻璃档位。现在所有面都是
「不透明基色 + alpha」两段，六个滑杆各管各的，毛玻璃只留 `backdrop-filter`
不碰底色。

**壁纸导入**：localStorage 装不下（5MB 上限，一张 1920 JPEG 转 base64 就 400KB），
所以走 IndexedDB。导入时 canvas 压到宽 1920 + JPEG q85，然后**跟内置那 9 张
用同一套逻辑量平均亮度**，导入的图也吃自适应遮罩。轮放序列合并内置 + 导入。

**降饱和**：`--primary` 从 `oklch(0.70 0.14)` 到 `oklch(0.68 0.085)`，彩度 −39%；
`--btn-content` 从 `0.55 0.12` 到 `0.50 0.075`；页面底、正文、按钮三态跟着各降一档。
大面积铺开时不吵了。
