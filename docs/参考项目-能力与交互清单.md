# 参考项目 —— 能力与交互清单

用户反复要求"**借鉴（不抄袭）**"这四个项目。这份清单是为了**看懂它们解决什么问题、交互怎么组织**，
给各模块的改造当设计地基。**下面写的都是我们自己的话**，只描述机制与形态。

**边界（硬规矩）**：不搬代码、不搬注释、不搬界面文案、不搬它的操作步骤文字；不反编译；
四个项目一律**只读**。

## 1. ja-text-tool —— 对应我们的 ① 日文乱码修复 + 翻译

### 1.1 它解决什么，工作流怎么走

三个页面各管一种活儿，靠**拖进来的文件类型自动分流**：

1. **粘贴文本**：粘乱码 → 点修复（还原成日文）；或直接翻正常日文；另有一个**"一键修复并翻译"**把两步合成一步；
   还有反方向（把正确日文转成乱码）用于对照与测试。结果可一键复制。
2. **批量文件**：加文件或**拖文件夹（递归找出文本文件）** → 选源编码（默认自动检测）→ 选处理内容（只转编码 /
   转编码 + 翻译）→ 选输出位置（另存到结果文件夹 / 覆盖原文件）→ 开始；
   设置区下方**实时显示"当前设置：N 个文件 → … → …"**，动手前先让人确认会做什么。
3. **着色器注释**：拖 `.fx` 等进来（按后缀自动进这一页）→ 点解析并翻译 → 在原文件旁产出**逐条对照的报告**
   （每条给：原始内容 / 还原出的日文 / **用的哪种还原方式** / 中文译文）；可选再生成一份带中文注释的副本，
   注释写成"日文 ｜ 中文"，代码原样；**原文件绝对不动**（用哈希核对过）。

### 1.2 值得学的机制（重点）

- **还原是翻译的前置步骤，而且会自己挑编码组合**：默认组合是"按 GBK 读错 → 还原成 Shift-JIS"；
  如果按这个组合还原不出假名，就**自动依次试**几个常见组合（GBK / Latin-1 / CP1252 / Big5 分别转 SJIS，
  以及转 EUC-JP），**取"还原出的假名最多"的那一种**，并把用的是哪一种显示给用户。
  → **翻译前一定是"先把乱码认成日文"，不是把乱码直接丢给翻译接口。**
- **文件编码识别有固定顺序**：BOM → UTF-8 → **cp932（Shift-JIS）** → GBK，都不行才降级。
  → 日文着色器"先按 Shift-JIS 认"是它的默认路径。
- **逐行保真翻译**：把每行拆成「行首空白 / 正文 / 行尾空白 / 换行符」四段，**只替换正文**；
  空行、缩进（Tab / 半角 / 全角空格）、行尾空格、换行符（含 CRLF）原样保留。
- **翻译提速三件套**：把多行**合并成一次请求**（按接口字数上限，免费接口约 420 字）→
  **多批并发**（但保守，只开 3～4 路，怕被限流）→ **相同内容去重并持久化缓存**。
  合并后**如果返回的行数对不上**（接口把换行吞了），就**自动退回逐行翻**，宁可慢也不破坏排版。
- **哪些行不翻**：文件页跳过"不含日文"的行（保护代码与格式、也省额度）；文本页反过来——
  用户点了翻译就是要翻，**哪怕内容是乱码也照翻**（早期因为跳过而出现"点了没反应"，后来改掉了）。
- **失败不静默**：结束时明确报"成功 N 个、失败 M 个"，失败**逐条列文件名与原因**，
  并明确说"失败的文件原封未动"，再给对策（换引擎 / 查网络 / 手动指定编码）。
- **覆盖原文件前先确认**（因为"只转编码不翻译"时看起来会像没变化），并**实时显示当前设置**；
  遇只读文件自动去掉只读后重试；写回时保留原有换行符。
- **设置自动记住**：改动后短延时自动保存，并**关窗再存一次**（填完直接关也不丢）；可一键清除；
  需要保密的密钥用系统级加密存，配置文件里看不到明文；也支持把配置放到指定位置（便携用法）。
- **引擎可选但默认给免费公开的那个**，另有一个"测试引擎"按钮，用来**区分"接口/额度问题"和"输入本身的问题"**。
- **屏幕适配**：空间不够时控件自动收缩、再不够就整页滚动（横竖独立判断）、滚轮可翻页，
  **任何窗口尺寸下控件都不会被裁掉**；窗口位置非法时安全回退，不崩。
- **拖拽不可用时给等价按钮**，不让人卡住。

### 1.3 它没做的 / 我们能更好的

- 只处理文本层面的乱码；**文件名里的乱码不管**（我们有"名字还原"这一页，是我们的增量）。
- 没有"候选列表 + 人工确认"那一层：它给的是"自动挑最好的一种"，**不给用户看其它候选**；
  我们的做法（够不着门槛时把候选与增益摆出来、让人点"就用这个"）比它更可控。
- 不处理工程文件（`.pmm`/`.emm`），与 ⑥ 不重叠。

### 1.4 映射到我们的模块

| 模块/分区 | 要改什么 |
|---|---|
| ① 全部 | 流程固定成 **乱码 →（按 SJIS/GBK 等组合还原成日文）→ 翻译**；还原那一步不许跳过，界面要显示"用的是哪种还原方式"。 |
| ① 文本页 | 加"一键还原并翻译"：把两步合成一步，新手不用理解两步的存在。 |
| ① 文件页 | 设置区下方**实时显示"当前设置：N 个文件 → 做什么 → 输出到哪"**，动手前先确认。 |
| ① 文件页 | 翻译提速：多行合并成一次请求 + 保守并发 + 去重缓存 + **行数对不上就退回逐行**。 |
| ① 文件页 | 结束报"成功 N / 失败 M"，失败**逐条列文件名与原因**，并明说"原文件没动"。 |
| ① .fx 注释 | 产出**逐条对照报告**（原始 / 还原日文 / 还原方式 / 译文），并可选生成带中文注释的副本。 |
| ① 名字还原 | 沿用我们已有的"候选 + 人工确认"，别学它的"自动挑最好就算"。 |
| ① 设置 | 引擎配置自动记住 + 可一键清除；有"测试引擎"按钮区分接口问题与输入问题。 |
| 全局 | 任何窗口尺寸下控件不许被裁掉（收缩 → 整页滚动 → 滚轮翻页）。 |

## 2. PMM V2 Path Editor —— 对应我们的 ⑥ 工程迁移

### 2.1 它解决什么，工作流怎么走

一句话：**打开一个 `.pmm`，把里面写死的"模型"和"附件"两类路径列出来，让人指到新位置，保存。**
没有"先选 `.emm`"这一步 —— 它的**文件过滤器只认 `.pmm`**（附件项认 `.x`），这也是用户说"拖入 pmm 就可以了"的依据。

### 2.2 界面组织（从它的文本资源读出的事实）

- 三个页签：
  - **模型**页：**名称** 与 **路径** 两组输入；
  - **附件**页：**只有路径**（没有名称）；
  - **设置**页：三组可折叠区 —— 物理（启用 / 物理地面 / 物理模式）、背景（WAVE / 图片 / AVI / 屏幕捕获 / 黑背景）、
    视图（相机光源追踪 / 自阴影 / 地面阴影及其透明 / 坐标轴 / 信息 / Fps 限制 / 分辨率）。
- 文件菜单：打开 / 保存 / 另存为 / 退出；另有语言与关于。
- 持久化：三个折叠面板的折叠状态与语言选择存在配置里。

### 2.3 值得学的机制

- **只让用户指"新位置"，不让人重新拖模型**：这是这个工具存在的全部理由，也是用户要的效果。
- **模型条目连"名称"一起可改**（不只是路径）—— 名称是工程里显示的东西，搬机器后常常也要改。
- **附件与模型分两页**，因为两者的处置方式不同（附件只有路径）。
- **顺带把 `.pmm` 里其它能改的字段也暴露出来**（物理/背景/视图那三组）——它不只是个路径编辑器。
- **折叠面板 + 状态记住**：默认全展开、可收起，下次打开保持原样。

### 2.4 它没做的 / 我们能更好的

- 没有"自包含打包"（不拷贝素材）。
- 没有"缺文件就把条目摘掉"（据前几轮量测）。
- 没有"按根批量替换"的批量入口（用户这次给我们提的正是这条：文件一个个挪走时也能处理）。

### 2.5 映射到我们的模块

| 模块/分区 | 要改什么 |
|---|---|
| ⑥ 入口 | **拖一个 `.pmm` 就够**：同名 `.emm` 自动接上并立刻出表，不再要求用户选第二遍。 |
| ⑥ 表 | **模型 / 附件分两块**呈现，各块给条数汇总；模型行显示**名称 + 路径**（名称可改，等长限制要写清）。 |
| ⑥ 表 | 每行的新位置**可直接编辑**（不只是"用这个"按钮）；能自动推断的就默认填好。 |
| ⑥ 写盘 | 保留"另存为"这一路（我们的默认就是写到指定目录），但**界面上要像这个工具一样直白**：打开 → 指位置 → 保存。 |
| ⑥ 附加 | 面板折叠状态记住（跟本工程其它页一致）。 |

## 3. ikClut-TextureTool —— 对应我们的 ② CLUT 调色

### 3.1 它是什么

Windows 桌面调色 + LUT 导出工具（C++20 / Qt6）。定位是"轻量调色工作台"：载图 → 调色 → 预览 → 导出给
MMD/MME 或其它流程；也能存工程与预设。

### 3.2 界面组织

- **主分隔条（左右）**：左边是**预览列**，右边是**参数标签区**，比例约 3:1，可拖动。
- **预览列里再分左右**：一个横向分隔条上并排放**两个独立的图片视图** —— 左边显示原图、右边显示结果图；
  **两个视图各自独立缩放与平移**（没有联动）。
- **顶部工具条**里有一个**预览模式下拉**：调色后 / 调色前 / 前后对比 / 快照 A / 快照 B
  （也就是"分屏对比"和"A/B 快照"两条比对路径都有）；另有 LUT 条形图视图与 3D LUT 查看器。
- **参数区**用两种容器组织：
  - **可折叠面板**：标题行点开点收，适合把一组长参数收起来；
  - **响应式标签面板**：一排放参数的**按钮条 + 堆叠切换**，按钮**按可用宽度自动换列数**，
    也就是"**固定板块 + 模式切换**"这种形态（不是把参数一路往下堆）。
- 底部/侧边还有示波器（RGB 与亮度分布、矢量示波器、曝光区间）与质量提示（假色/裁切/色域）。

### 3.3 值得学的机制（重点）

- **图片视图自己带缩放与平移**：滚轮缩放（有上下限，约 0.1×～12×）、按住左键或中键拖动平移、
  有"重置"（缩放归 1、平移归 0）；图像按"居中 + 平移偏移"渲染。**原图和结果图各有一个这样的视图**，
  所以用户可以对左右两边分别放大到同一处细节比对。
- **参数面板按"模式切换"组织**，不靠长列表：切换成本低、每屏只显示一类参数。
- **两档预览质量**：交互档按上限缩小图像（跟得上手）、完整档按原尺寸；
  渲染优先用 GPU，不行回退 CPU，并**把耗时与用的哪个后端报出来**。
- **能力清单本身就是设计参考**（它的调色项）：基础（曝光/对比/饱和/自然饱和/色温/色调/高光/阴影/白场/黑场）、
  曲线（主 + RGB 三条，另有色相-色相 / 色相-饱和 / 色相-亮度三条）、HSL 八色段、色彩变形（源点→目标点映射）、
  专业项（Lift/Gamma/Gain/Offset、Log/HDR 分区、Printer Lights、肤色、校准、Soft Clip）、
  LUT 导入导出（3D CUBE、纯 1D 烘焙成 3D、Hald PNG）、批量套用到图像、工程与预设保存、
  节点图（串行 / 混色 / 并行混合 / 图层混合，带"环"与"输出未连接"诊断）、质量检查（LUT 检查、示波器、假色）。
- **明确拒绝做不到的输入**：混合了 1D 与 3D 的 CUBE 文件**直接拒绝**，不静默导入一个错误结果。
- **预设与工程分开**：工程绑图像路径，预设只存调色参数（可复用到别的图）。
- 会话性布局（节点位置、视图、面板尺寸）存在工程旁边的会话文件里，删掉即恢复默认，不动素材。

### 3.4 它没做的 / 我们能更好的

- 局部遮罩编辑这版被移除（交互不够可靠）。
- 节点图不是通用 DAG（作者自己写在限制里）。
- 资源以路径记录，**外部图/LUT 移动后旧工程要重新指定**（作者写在文档里）——
  这条正好是 ⑥ 要解决的场景，两家可以互相补。

### 3.5 映射到我们的模块

| 模块/分区 | 要改什么 |
|---|---|
| ② 预览 | **原图 / 调色后两个预览各自可缩放可拖动**（滚轮缩放 + 拖动平移 + 一键重置）；不是只把框做大。 |
| ② 预览 | 加**前后对比与快照 A/B**：能一键切"只看原图 / 只看结果 / 并排对比 / 跟快照比"。 |
| ② 参数区 | 改成**固定板块 + 模式切换**（基础 / 曲线 / HSL / 色轮 / 变形 / 专业 / 节点 / LUT），
  每组内部再用可折叠面板收长项；**不许一长条往下堆**。 |
| ② 参数区 | 参数按类型给对应控件（滑杆 + 数值框、向量分量各自范围、颜色选择器、枚举下拉、
  **只有真有开关语义的才给开关**）。 |
| ② 质量 | 预览分两档（拖动档小、停手补细图）—— 我们已有，保留；把耗时与"当前用的哪一档"报给用户。 |
| ② 导入 | 混合 1D+3D 的 CUBE **明确拒绝**并说原因（已有类似行为，确认文案到位）。 |
| ② 工程 | 调色参数可存成**预设**（不含图），工程另存（含图路径）。 |

## 4. Editor-For-MMDStarRail4Fun —— 对应我们的 养乐多 / 渲染联动（Ray）

### 4.1 它是什么

面向某套星铁仿渲 shader 的**固定管线材质编辑器**（C# WinForms + WPF 检查器）。
它明确**不含也不下载任何 shader/模型/贴图**：每次启动让用户选自己那份 shader 文件夹，只有用户点保存/导出才写盘。

### 4.2 界面组织

- **顶部工具栏**：打开 / 保存 / 另存 / **导出包** / 导出 VMD / 撤销 / 重做 / **适合画布** /
  **检查资源** / 诊断（展开收起）/ 使用说明。
- **左侧**：当前文件（六份角色材质 + 两份阴影 + 只读参考 + 控制器）、**参数或源码名搜索**、
  **参数分组**（按功能分：基础颜色、卡通阴影、高光、边缘阴影、星空…）、
  **"显示全部参数"开关**（**常用 / 完整 两档渐进展开**）。
- **中央**：**固定管线节点画布**（节点只用于导航，**不能新增、删除、自由连线**）；
  另有**源码视图**（只读、可查找/复制/定位行、行边上有"已改未保存"与"当前定位"标记）；
  底部**诊断面板**集中显示缺失纹理、绝对路径、核心文件缺失等问题。
- **右侧检查器**：点节点或左侧分组后显示该组参数；**中文名作主标题，下面用等宽字给出原始源码 ID**；
  说明文字写用途与单位。

### 4.3 值得学的机制（重点）

- **"不用先选完就能改"是怎么做到的**：**参数始终在右边摆着**，左侧的"文件 / 分组 / 搜索 / 显示全部参数"
  只是**筛选与导航**；点哪个参数改哪个 —— 没有"必须先选定某一行才能编辑"的门槛。这直接对着用户那句
  "必须选完了才能改就是很垃圾的操作"。
- **渐进展开（常用 / 完整）**：默认只显示最常用的少数几项（来源、纹理、材质 0、全局强度），
  打开"显示全部参数"才展开材质 1–7、UV 变换、底层向量。新手不被淹没，老手一步就能展开。
- **按参数类型给对应控件**：滑杆（快速试）+ 数值框（精确）；向量各分量**各自范围**（不会被颜色的 0–1 夹住）；
  颜色色块；**枚举下拉**；**只有真的有开关语义（对应一个 define）才给开关**；
  纹理路径给"选文件"按钮并**用三种颜色标状态**（可访问 / 用了绝对路径的提醒 / 启用中却缺失）。
- **保存是原子的**：同目录临时文件替换 + **自动备份保留最近 10 次**；失败时**不清空当前修改**，
  解决后能再保存；撤销/重做按"一次完整拖动算一次、下拉/开关/选纹理各算一次"计量。
- **导出包 = 先预检、再在临时目录里组装**：有任何启用中的资源缺失就**列出来源且不产出**；
  通过后把需要的文件拷进临时 staging、**把包内路径改成相对路径**，最后才落到输出目录；
  输出目录重名时**自动选一个唯一目录**，不覆盖旧包；完成后打开输出目录。
- **诊断项可双击定位**到对应参数，再重新选正确文件（错误与"去哪儿改"绑在一起）。
- **错误说明必须包含恢复方向，并保留用户输入**（写在它的设计约束里）。
- **设计约束里有几条通用原则**：画布/主视图优先，参数面板不许把主视图挤到读不了；
  单一强调色；**面板不是装饰卡片**（禁止卡片嵌套、大圆角容器）；
  **禁止用颜色作为唯一状态信号**；禁止把固定阶段伪装成可任意连线。
- **只读参考与可编辑内容分开**：参考源码只读（可搜索、可复制，不能改），也不公开实现级常量。
- 会话状态（节点位置、视图、面板尺寸）存工程目录旁，删掉恢复默认，不影响被编辑的素材。

### 4.4 它没做的 / 我们能更好的

- 只支持一套固定管线的 shader，不通用（我们是面向多游戏/多套包）。
- 需要 .NET 运行时；我们是单文件 Tauri 程序。
- 它的"节点"是固定导航图，不是可编辑流程图（用户原本也想"节点"——我们已按"可增删重排的处理链"做，
  与它的"固定阶段只导航"取向不同，这点要跟用户确认哪边优先）。

## 5. 四个项目共同的交互原则（"新手友好"落到做法上）

1. **主操作一步到位**：能合成的两步合成一个按钮（"一键还原并翻译"），别让新手理解内部步骤。
2. **默认值 + 自动识别优先**：编码、引擎、分组、材质 0、输出位置都给好默认；人工只在必要时介入。
3. **参数永远可改**：分组/选中只是筛选与导航，**不设"先选完才能改"的门槛**。
4. **失败不静默**：逐条给文件名与原因，明确"原文件没动"，并给对策；错误说明要含"怎么恢复"。
5. **危险操作先确认、默认推荐安全项**：覆盖原文件前先问，默认走另存；写盘留备份。
6. **先预检再产出**：不合格就不生成半成品（导出包那套），并把不合格项列出来、可双击定位。
7. **长参数区靠"分组切换 + 可折叠"，不靠往下堆**。
8. **状态用文字 + 颜色双通道**（不许只靠颜色）。
9. **预览要能自己看**：缩放/平移/前后对比/快照，原图与结果各自可控。
10. **设置自动记住、可一键清除**；安全相关（密钥）加密存。
11. **任何窗口尺寸下控件不被裁掉**（收缩 → 整页滚动 → 滚轮翻页）。
12. **拖拽是加分项不是唯一入口**：拖不了时必须有等价按钮，并说明原因。
