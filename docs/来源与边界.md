# 来源与边界

> 这一页是给"这东西是不是抄的"这个问题准备的。结论就一句，下面是它的具体含义。

**本工程不含、不分发任何第三方渲染包或工具；未复制其代码；
规格来源只有三条 —— 公开文档、本工程自己对着素材量出来的实测、以及用户口述的自己那套做法。**

---

## 1. 不含、不分发

发布物只有 `dist\` 里那两个 exe 加一个 `说明.txt`。里面**没有**任何第三方渲染包或工具：

- 不打包 Ray / 养乐多 / msToon / ikClut 这些渲染包，也不打包任何别的贴图工具。
- `src-tauri/tauri.conf.json` 的 `bundle` 里没有 `resources` 项，安装包除了本工程自己的代码什么都不带。
- 渲染包一律由用户自己在设置里指路径；本工具只在那条路径上读写文件，
  改动前留 `.bak`，不主动动别人的东西。

研究用的素材（各种第三方包、样本图）放在**本仓库之外**的
`E:\deepseek-harness\mmd集成工具\参考工具样本\` 下，从不进仓库、也不进发布物。
`.gitignore` 里也留了一条备用。

## 2. 不复制代码、不搬说明、不照搬操作方式

三条一起成立才算数：

| 不做什么 | 具体意思 |
| --- | --- |
| 不复制代码 | 一行都没有。算法要么是标准算法（直方图匹配、双线性缩放、Sobel、距离场），要么是本工程自己推的 |
| 不搬说明 | 别人的注释、手册、界面文案不进本工程的注释和界面。参数说明按"这个参数是什么、调了会怎样"自己写 |
| 不照搬操作方式 | 界面怎么组织、一步要做几件事，按本工程自己的需求定 |

**"对着素材量"和"看别人的实现"是两件事。** 前者是本工程唯一认的地面真值：
同一目录、同一套 UV 的「输入 → 产物」逐像素比，比出来的数字是本工程自己的观测事实。
后者不碰 —— 参数说明里不写"它内部怎么算的"，因为那是实现细节，不是规格。

已经按这条清过一轮（2026-09-19 那次避嫌）：删掉了从别人可执行文件抽字符串的脚本
和读别人 Electron 包的脚本；注释里点名别家工具的地方改成"素材里那份产物"这种讲事实的说法；
参数说明里"源码里是 `for (...) {...}`"这类整段实现叙述改写成对参数的直述。

## 3. 规格从哪来

只有三个来源，每个数字都能追到其中一个：

1. **公开文档** —— 渲染包自带的 `readme` / `ray.conf` 注释 / `.fxsub` 里的参数定义。
   这些文件本来就在用户机器上，本工具的正常工作就是要读写它们。
2. **本工程自己量的实测** —— 对着真素材出数字。主要判据：
   - 同一目录、同一套 UV 的「输入 → 产物」配对，**先要 bit-exact**，对不上再看平均差；
   - 30 张真实 ramp 量出来的尺寸与行结构；
   - 绝区零 `_A / _M / _N → LM` 的真实配对（R 与 B 两路逐像素相同）。
3. **用户自己画 ILM 的做法**（用户口述的一手流程，不是从别处看来的）。
   用户自己画的 ILM 那套通道含义与硬规矩只认这一条：
   - R = Gloss 光泽、G = AO、B = Specular、A = Line（线：黑底与线 = 0，其余 = 1）；
   - R/G/B **不许填纯黑纯白** —— 0 = 永久阴影、1 = 永久光照，所以出图夹在 0.05~0.95；
   - 做法：SP 里纯色填色 + 整块黑底 + 导出溢出 1 像素 → PS 修成横平竖直矩形 →
     A 用魔棒选黑填 0、其余填 1 → 存 TIF/TGA 才保得住四通道。

   **这条和「游戏那张 lightmap」不是一套约定。** 游戏 lightmap 的通道含义是第 2 条量出来的
   （R 高光/反射、G 阴影基调、B 金属度、A Ramp 层索引），两者不能互相当靶子 ——
   照这条约定试出来的 G / B / A 数字只能当记录，不能当验收。

   （曾想引一篇知乎文章当参考，三次都打不开：直连 403、镜像连不上、
   真浏览器返回"当前请求存在异常"。所以这条路上**没有一个字**来自外部资料。）

4. **用户口述的流程**（2026-09-20 给的，他自己整理的三份做法）—— 只取"哪个通道是什么、默认填几"
   这类**事实**，教程原文、操作步骤、界面文案**一个字都没搬进来**。落点在
   `src/lib/modules/channels/conventions.ts`，界面上每条都标了来源（`用户口述的流程` / `本工程实测`）。
   - 光照贴图那套：R 金属度、G 环境光遮蔽（默认 0.5，只有永不受光处填 0、永远发光处填 1）、
     B 高亮反光（默认 0，跟 R 一起用才有效）、A 发光（皮肤一般 1、衣服一般 0）。
   - 三渲二金属度那套：R 金属/反光（皮肤与浅色布料 1、深色布料 0.5、金属 0、晶体约 0.8、眼睛 0）、
     G AO（默认 0.5）、B 高光（默认 0，一般只有金属与头发有）。
   - **这两套跟本工程从模型库量的那套（R 高光/反射、G 阴影基调、B 金属度、A Ramp 层）不是一回事**，
     所以工具里让用户先选"按谁的约定画"，不替他把两套混起来。

   另外用户提了三个游戏的着色算法（**星铁 Blinn-Phong、绝区零 matcap + 高光、原神 GGX**）——
   这条只记在这里，用途是"解释为什么三套约定本来就不该一样"，**没有据此改任何公式**
   （改公式要有实测支撑，不能靠算法名字推）。

配对实测的完整记录：`docs/产物配对实测.md`。
这些数字是**本工程自己量的**；素材本身（样本图、包、exe）不分发。

## 4. 名字怎么处理

界面上出现的 `ikClut`、`msToon`、`Ray`、`养乐多` 这些词，
指的是**渲染包 / 着色器本身**，不是某个别的工具：

- `ikClut` —— 那个包的着色器就叫 `ikClut.fx`，本工具对齐的是它的 CLUT 排法，不写这个名字就没法说清对齐的是什么。
- `msToon`、`Ray`、`养乐多` —— 同上，是渲染包的名字。
- 别的**工具**的名字（各种 Converter / Studio / Painter / Editor 的 exe 名）
  在界面和代码里一个都没有。

这条界线是：**引用渲染包的名字是必要的说明，引用别人工具的名字不是。**
