# 开发者指南

跑起来、改代码、验改动、发版。**给写这个工程的人看**，不给用户看。
用户那份是 `docs/使用说明-新手向.md` 和 `dist/说明.txt`。

---

## 1. 三分钟跑起来

```powershell
pnpm install
pnpm dev            # 浏览器里调界面 → http://127.0.0.1:1420
pnpm tauri dev      # 真桌面窗口，能测后端
```

**浏览器和真窗口不是一回事。** ①③⑥⑨ 和所有真文件读写都走 Rust
（`read_rgba` / `scan_dir` / `saveBytes` / 那几个 `#[tauri::command]`），
浏览器里会明说「这个功能要在桌面端跑」。**改后端、改读写，必须开 `pnpm tauri dev` 验。**

第一次 `pnpm tauri dev` 要编 Rust，慢；之后增量很快。

## 2. 改完先跑基线

```powershell
pnpm test                                    # 期望 40/40（38 套前端 + ilmcheck + cargo）
pnpm exec svelte-check --threshold warning   # 期望 0 错 0 警
```

`pnpm test` = `node tools/run-tests.mjs`，一条命令跑三样：

| 跑什么 | 在哪 | 现在 |
|---|---|---|
| 纯逻辑单测 | `tmp/*.test.mjs`（38 套） | 全绿 |
| ⑤ 真实配对（对着素材） | `tmp/ilmcheck/run.mjs` | 全绿 |
| Rust 单测 | `cargo test --lib` | 137 passed |

单跑一套：`node --import ./tmp/register-loader.mjs tmp\xxx.test.mjs`。
⑤ 那套自己挂 loader，**别带 `--import`**。

> **`svelte-check` 假红**：受限沙箱下 vite 载 `vite.config.js` 要 spawn 子进程，被挡就是
> `spawn EPERM` → 全库预处理失败 → 报「35 errors in 35 files」。**先找 `EPERM`。**

> **浏览器里改完记得看 `pi` 那条**：HMR 之后应用引的是 `…?t=…` 那个 URL，
> 探针直接 import 裸路径会拿到**另一个空实例**（落点表 / 注册表全是空的）。
> 要从 `performance.getEntriesByType('resource')` 里把带时戳的 URL 找出来再 import。

**加新功能看 `docs/加新模块.md`。** 两条会被 `tmp/perf-guard.test.mjs` 守住：
注册表不许**静态** import 分区组件；进场观察的回调里不许全文档查询。

顺带一条 **Svelte 5 的坑**：`{#each}` 带 key 且 key 重复会 **throw**，
整个块直接不渲染（页面上就是"点了没反应"）。渲染列表一律
`{#each 列表 as x, i (i)}`，别拿可能重复的字段当 key。

## 4. 界面规矩

看 `docs/工作区界面规范.md`。最常踩的四条：

1. 侧边导航**不许出现 ①②③ 序号**；错误显示在**侧边导航栏**（`setErr`）
2. **一个页面只有一颗主按钮**（`btn--primary`）；`tools/ui-audit.mjs` 会数，多一颗就红
3. 动效不许有过冲
4. 模板里**不许出现 `**粗体**` 这种 Markdown 残留**（用 `<b>`），`tmp/ui-text.test.mjs` 守着

改完界面跑一遍全路由审计：

```powershell
node tools/ui-audit.mjs --all
```

## 5. 拖放

拖放是两条路一起接的，**改一边要看另一边**：

| | 什么时候走 | 在哪 |
|---|---|---|
| 原生 | Tauri 桌面端 | `getCurrentWebview().onDragDropEvent` 给的是**真路径** |
| HTML5 | 浏览器 `pnpm dev` | `dataTransfer.files`，**没有真路径** |

- 落点注册表是 `dropzones.svelte.ts`。通用落点（不只图片槽的地方）用
  `registerZone`；只收文件夹用 `src/lib/dirdrop.ts` 的 `接目录` action。
- 高亮类是 `.is-drop`，样式在 `src/styles/wb.css`。**别再加 `[data-drop-target]` 那种限定** ——
  那个属性大部分落点没写，加了就等于没高亮。
- 原生那条路的坐标是**物理像素**，要 ÷ `devicePixelRatio` 才是 CSS 像素。
- 拖放测试：`node --import ./tmp/register-loader.mjs tmp\拖材质链.test.mjs`。

## 6. 怎么验（这是这个工程最看重的一节）

**别拿"看着像对的"当结论。** 这个工程为自信的错误结论吃过两轮亏。

- 探针写 `tmp/probe-*.mjs` / `tmp/验收-*.mjs`，跑完留在盘上，**写进 `PROGRESS.md` 的是实测数字**。
- 量之前先证明**仪器本身能复现这个场景**。吃过一次：`read_rgba` 的桩返回
  `{data}` 而不是 `{rgba}`，于是"每一页都填不出东西"——是桩坏了，不是代码坏了。
- 视觉模型（`mcp__vision-mmd__*`）**不可靠**：`qwen3-vl:4b` 对尺寸、计数、逐行结构
  经常是照着文件名在推。定性看可以，**承重事实必须用像素测量复核**。
- **别拿探测超时下"连不通"的结论。** `Invoke-WebRequest -Method Head` 对 github / CDN
  全超时，但其中有的实际通。要用真客户端跑一次。

真机截图 / 审计（`pnpm dev` 要在跑）：

```powershell
node tools/cdp-shot.mjs tmp/x.png 800 "http://127.0.0.1:1420/"   # 截图
node tools/cdp-audit.mjs                                         # 所有路由跑一遍，抓运行时错误
node tools/cdp-lazy-check.mjs                                    # 这一趟拉了哪个模块
node tools/ui-audit.mjs --all                                    # 布局与主按钮审计
```

打包版的探针要**自己的 WebView2 用户目录**，否则第二个进程会挂到已有浏览器进程上、
`--remote-debugging-port` 不生效：

```powershell
$env:WEBVIEW2_USER_DATA_FOLDER="$env:TEMP\robin-cdp-profile"
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS='--remote-debugging-port=9222'
pnpm tauri dev
```

无头 Chrome 那类探针：

```powershell
chrome --headless=new --remote-debugging-port=9500 --window-size=1707,1067 `
       --user-data-dir=$env:TEMP\robin-probe
```

收尾记得杀掉占 9500 的 chrome、删 `%TEMP%\robin-*`（长路径要 `\\?\` 前缀）。

## 7. 改文本文件的硬规矩

**只用 read / edit / write 工具，绝不用 PowerShell 的 `Set-Content` / `Out-File`。**
用过一次，给一个 `.svelte` 加了 BOM，靠临时脚本才按字节摘掉。

写回时：

- **原文的编码和 BOM 必须保住。** 前端拿到的 `text` 是**剥过 BOM** 的，
  "整段重写"那条路要把它接回去（`ray/Ray.svelte` 里 `接回BOM`）。
  能走"字节拼接"（`spliceAsciiLineEdits`）就别走整段重写 —— 那条路搬的是原始字节，最稳。
- 行尾按原文那种（`detectEol`），别统一成 LF。
- 解码有损（`lossy`）时要如实报，别让写盘那条路静默改写。

## 8. 发版

```powershell
pnpm build            # 前端出到 build\
pnpm tauri build      # 出安装包（.msi）与绿色版（.exe）
```

打完把两个产物拷进 `dist\`，然后：

```powershell
node tools/exe-frontend-check.mjs      # 核包里嵌的前端是不是刚构建那份（chunk 名是内容哈希）
                                       # **要 42/42 全中才算过**：没改过的文件名字不变，
                                       # 旧包照样能中一大半（这个工具的结论原来写成
                                       # hit>0，2026-09-26 抓过它一次假的绿）
node tools/bundle-report.mjs build     # 首屏链多少 KB、最大 chunk 里装着谁
node tools/check-lazy-chunks.mjs build # 按 URL 把按需 chunk 取一遍
```

再核对 `dist\说明.txt` 里的体积数字。

**`build\` 是构建产物，改了源码不重建的话，`dist\` 里那两个 exe 还是旧的。**

> 绿色版**正在运行的时候拷不进去**（文件被占用），先关掉应用。

`.gitignore` 里已经排除了 `dist/*.exe`（只留 `dist/说明.txt`）、`src-tauri/target/`、
`tmp/chrome-audit/`、`tmp/ilmcheck/data/`。
