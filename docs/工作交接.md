## 3. 验证信条（最重要的转移）

这个工程吃过最大的亏是**拿错参照还自信地给出结论**。下面每条都是拿真实代价换的：

### 3.1 配对是唯一能出事实的东西

**同一目录、同一套 UV 的「输入 → 产物」才是地面真值。** ⑤ 卡了两轮，就是因为拿 `GI_Converted_Body_Lightmap.png` 当参照，而那张的 R 通道整片是 0，跟喂进去的源根本不配对。

正确的一对长什么样（这就是最终通了的那个）：
```
实战测试用例\渲染联动\养乐多\MMDStarRail4Fun_v2.2.1\ZZZ\vivian\
  Vivian_Body_1_{A,M,N}.png  →  Vivian_Body_1_LM.png     ← 同目录
```
验出来的映射：`LM.R=_A.G`（100% 逐像素）、`LM.B=_M.B`（100%）、`LM.G=_N.B`（corr +0.998，差的是重采样）。

**先用 R/B 两路 bit-exact 确认配对成立，再谈 G 路。** 两路逐像素相同不可能是巧合。

### 3.2 拿不到配对时，只承认"配比对齐"

原神 / 星铁那两套没有配对，只能对齐各档占比而已，最佳 IoU 只有 0.39。**这种结论要标成"配比对齐"，不能写成"映射成立"。**

### 3.3 像素测量 > 视觉模型

本机装了视觉 MCP（见第 6 节），但它是 4B 模型。实测让它描述一张 256×20 的 ramp：说「20 行完全相同、颜色浅蓝到淡紫」，**实际是 10 对不同的行、值为 (209,215,215) 的近灰**。再问细一点它就不看图了，转而照着文件名和尺寸推理。

**定性看可以用，尺寸 / 计数 / 逐行结构 / 具体像素值一律用像素测量复核。**

### 3.4 区分"测试痕迹"和"真 bug"

判据（已固化成断言）：
- **差异只出现在 alpha<255 的像素上，且 maxDiff = 1** → 是数据痕迹，不是你的 bug
- **任何出现在 alpha=255 像素上的差异** → 是真 bug

实例：`LM.R` 有 0.033% 差 1 级，全部落在 `_A` 的 alpha=254 像素上（全图只有 0.40% 的像素 alpha<255）——那是作者工具走了一趟预乘/反预乘留下的。

### 3.5 别被"完全相同 %"骗

走重采样的通道永远到不了 100%。`LM.G` 的「完全相同」只有 84~90%，看着像差很多，**实际平均差 0.13 级 / 255，等于对上了**。要报就报 MAE（平均差），别只看比例。

### 3.6 测试自己也会骗人

写 `tmp/ramp-ops.test.mjs` 时把 `ok()` 的参数顺序写反了（写成"标签在前、条件在后"，而其它套件是"条件在前"），**非空字符串恒为真，整套 55 条"通过"全是假的**。是真实文件的断言把它打回来的。

现在那个文件里有段自检：故意传一个 `false`，如果没被记成失败就直接 `process.exit(1)`。**新写套件时照抄这段。**

## 5. 环境坑（都踩过）

| 坑 | 现象 | 应对 |
|---|---|---|
| **PowerShell 改文本会把文件搞坏** | 加 BOM、转 CRLF、中文变乱码 | **只用 read/edit/write 工具改文本文件**，绝不用 `Set-Content` / `Out-File` |
| `application/json` 触发 CORS 预检 | 本地小服务器收不到 POST | 用 `content-type: text/plain` |
| 浏览器 canvas 是预乘 alpha | `createImageBitmap`+`getImageData` 读回来 RGB 被改（alpha<255 差 ±1，alpha=0 直接抹掉） | 走 Rust 的 `read_rgba` 拿原始字节 |
| TGA 没有魔数 | `image::load_from_memory` 认不出 | `fsops.rs` 里已有"先魔数、失败再按扩展名"的兜底 |
| github.com 不通 | `npx skills add` clone 失败（Connection reset） | 走 skills.sh 的 JSON 接口，工具见 `E:\deepseek-harness\collection\fetch-skill.mjs` |
| CDN 不通 | `cdn.tailwindcss.com` / `cdn.jsdelivr.net` 超时 | 需要网页产出时**写成全内联样式 + 手绘 SVG**，别挂 CDN |
| `dist\RobinEditor-免安装版.exe` 被占用 | 用户正在运行就拷不进去 | 确认没在跑，或先staged成别的名字 |
| 截图看不到 | 本模型不接受图片输入 | 用数值核验（区域方差、唯一色数、均值标准差）；或走视觉 MCP |
| **HEAD 探测不可靠** | `Invoke-WebRequest -Method Head` 对 github / CDN / ollama registry **全超时**，但其中有的**实际是通的**（ollama registry 实测 13 MB/s 拉得动） | 别拿探测超时下"连不通"的结论——**用真客户端跑一次**。本会话就因此错判过 MiniCPM-V |
| C: 只剩约 4 GB | 装任何模型/大依赖都会撑爆 | 模型一律装 `E:\AI_models`（`OLLAMA_MODELS` 已固定）；大文件放 D:/E: |
| **`svelte-check` 会假红** | 受限沙箱下报「**35 errors in 35 files**」，其实一个错都没有 | 看有没有 `spawn EPERM`：vite 载 `vite.config.js` 时 `optimizeSafeRealPathSync` 要 spawn 子进程，被挡就整库预处理失败。给足权限重跑同一条命令即 0/0 |
| `cargo test` 假报 exit 1 | 明明 `36 passed` | cargo 把进度写 stderr，PowerShell 包成 `NativeCommandError` 把退出码带成 1。单独跑一次看 `EXIT` |
