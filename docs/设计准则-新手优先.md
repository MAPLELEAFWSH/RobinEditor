# 设计准则：新手优先（2026-09-23 起，全站有效）

用户原话："**你要根据我的需求调整设计界面操作排版布局，最大化便利新手使用为主要目标，
因为你是设计师你是开发者**"。→ 这份准则高于此前所有界面规范里冲突的部分（§一~§十八 里与它冲突的，以本文为准）。

## 一、一条主线，一眼可见

- 进页面**顶部一句话**说清"这一页干什么"；**第一张卡就是下一步该做的事**，不让人猜顺序。
- **每页只有一条主线**：素材 →（自动处理）→ 结果 → **唯一主按钮**（底栏）。其余全部收纳（§十八）。
- **主按钮的必填项不折叠、不藏抽屉**；主按钮上写**动词 + 对象**（"原地修好""打包到输出目录"），不写"提交/执行/确定"。

## 二、自动优先：能算的全算好

- 能从工程/素材推断的**默认填好**（旧根、新根建议、输出目录建议、编码、尺寸、模板、通道约定）。
- **人只做两件事**：确认，或在候选里**挑一个**。**不许让新手从零填路径**。
- 推断不唯一时：**给推荐项 + 其余候选列出来**，一句"为什么推荐它"。

## 三、一次只问一个问题

- 任何一个需要判断的地方：**选项 ≤ 3 个，推荐项排第一并标出来**，另给"我自己填"。
- **不许一次甩出五个选择**或一次性给十个字段让人填。

## 四、说人话，就地反馈

- 错误/提示 = **发生了什么 + 你该做什么**（例："这些路径指向 `D:\…`，本机没有 → 给它指定一个新位置"），不写术语、不写内部字段名。
- **不弹窗、不跳页**：状态就地变（表里那行变、按钮变、底栏一句）；错误走侧栏 + 就地两句。
- **提示超时自动消失**（沿用 9 秒那条），**只有"要用户决定的确认"不自动关**。

## 五、一步一个结果，随时能退

- 每个动作后**立刻给可见结果**（表/读数/高亮/一句话总结），不让人怀疑"点到了没有"。
- **任何写盘都能一键撤销**（先出表说清会动什么 → 确认 → 执行 → 回读核对）。
- **重置**（清界面、不动文件）与**撤销**（动文件）**分开**、写在界面上。

## 六、不许卡

- 任何可能超过 ~1 秒的操作（大目录扫描/检索/整链重算）：**后台跑 + 进度 + 可取消**；
- **范围失控要早拒绝**：选到盘根这种宽泛目标，**立刻回"范围太大，请给更具体的起点"**，不许把界面卡死；
- 拖动/连敲时**先出粗结果**，停手再补细（两级预览那套口径推广到别的重算场景）。

## 七、全站一致

- 同一件事：**同一个词、同一个位置、同一个手势**（例：写盘永远在底栏；"选…"永远在行的右侧；拖动永远可拖到"行"与"卡片空白"两处）。
- **一个动作只有一个入口**（谢绝重复）；**一组数字只出现一次**。

## 八、容量与排版

- 一屏主线控件 ≤ **8**；长列表/长路径**可折叠**（收起时标题带关键读数）。
- 长路径**换行显示**、绝不重叠/溢出/横向滚动；**写盘条永远不被任何底栏遮挡**。

## 十、新手默认，兼顾老手（用户 2026-09-23 补充）

用户原话："**还需要有留给老手的自定义操作空间，新手为主，兼顾老手的自定义**"。
→ 界面分**两层**：**默认层（新手）** 与 **自定义层（老手）**，**默认层永远可用且不用配置**；
老手要改的东西**一层之内找得到，但不挡新手的路**。

**怎么分**
1. **默认层（打开就能用）**：所有推断/默认值/推荐项；主线与唯一主按钮；收纳起来的常见卡。
2. **自定义层（想要才展开）**：
   - **同一个设置点，给"默认 / 自定义"二选一**（例：新根 → "自动找的推荐值" 与 "我自己填"；打包 → "本机内 / 配布"；通道约定 → "按游戏默认 / 自定"）；
   - **专家参数收进该卡的「更多设置」**（不外露、不占主线控件数）；
   - **批量/脚本向的操作**（按目录名整批改、按映射表改、正则、导出参数模板）放在「更多工具」或该卡的展开区；
   - **能被老手接管的地方要能"松绑"**：自动推断出的值一旦被手动改过，**就不再被自动规则覆盖**（并且界面上标出来"这是你手动定的"）。
3. **不许出现"只有老手才会用所以藏起来的功能"**：藏可以（收纳），但**入口要在同一个地方、同一个词**，不搞隐藏菜单/隐藏快捷键才有。
4. **老手的面子**：**快捷键、批量、幂等重跑、可复现的参数导出**这些要有（老手靠这个省时间），但**不许成为新手的必经步骤**。
5. **验收补一条**：新手脚本（§九）走通之后，**老手脚本**也要走通 ——
   ① 用**自定新根**（不靠推荐值）修一份工程；② 用**配布打包**发一份；③ 用**批量**对一整个目录跑同一种处理。三步都不需要"先关掉某个自动行为"。

## 十一、怎么算做到（验收口径）

用一个**"新手脚本"**验：不看任何文档，只按界面上的文字，能否在 **3 分钟内**完成这三件：
1. 把一份"文件被挪走"的工程**修好并能打开**；
2. 把一份工程**打包**成一个自包含目录；
3. 调一张 LUT 并**导出**。
任一步"需要猜下一步该点哪"或"卡住超过 1 秒没反馈"，都算没做到。
